## 2. 第二轮：持久故障、重开与边界

发现：
1. 真实 `SqliteStore._check_clock` 以秒比较 wall 与 monotonic；初版把毫秒传给 `monotonic`，导致 `clock_changed`。
2. `execute_run` 会在循环中多次调用 `active_clock()`，而部分 store 操作使用循环顶部捕获的 `now_value`；共享 `current_ms` 会在捕获后继续前进，造成 store 时钟采样错位。
3. 不同子运行共享同一 profile 时，墙钟必须跨运行单调；初版每个子运行从 0 开始，第二个子运行被 `clock_changed` 拒绝。
4. `execute_run` 在 `wall_start/now` 与 `mono_start/now` 之间按调用顺序采样，墙钟需与即将读取的单调值保持一致，否则 S06 round 秒被误判为漂移。

修改：
- `_MeasuredStore` 在每次真实 store 调用前把注入时钟同步到该调用的显式 `now`（秒单位），保证 wall/mono 增量一致；真实 `execute_run` 仍是唯一调度链。
- `_Clock` 增加跨运行 wall 基准（`set_base`）与 peek-式墙钟：未显式漂移时 wall 与即将读取的 mono 同增量；S07 `clock_changed` 用显式 `wall_step_ms=1001` 制造真实 >1s 漂移。
- S06 按 `execute_run` 的实际调用序注入 mono 序列（run start / last_boundary / loop top / job start / job elapsed），等于/超限行为来自真实 `_spend`/`_handle_job`/`BudgetState`，不预填计数。
- S07 renew 用真实 `claim_job/start_job/renew_job/finish_job/current_lease_expiry` 与显式 20s 时刻；终态后与旧 Lease 续租均被真实仓储拒绝；`waited_ms` 用真实 `build_stage_preempted` 单调差。
