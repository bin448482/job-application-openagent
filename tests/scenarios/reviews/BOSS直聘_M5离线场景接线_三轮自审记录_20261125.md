## 二、第一轮：独立 oracle 与原始刺激隔离

1. **刺激文件不含产品结论**：新增 `fixtures/m5/stimuli/actions.json` 只含 before/
   readback/dialog/after 原始 XML、IME、点击坐标、不可逆序号与故障变形；没有
   performed/eligible/隔离/重试/期望字段。原 `fixtures/m5/actions/fault-matrix.json`
   保留但不再作为新增探针输入。
2. **假设备只模拟外部事实**：`m5_probe.py` 的 `_Device` 只按 argv 返回原始终端输出、
   IME 与 returncode，并独立计数全部命令与可能不可逆点击；它不返回动作结论。产品
   结论全部由真实 `perform_action`/`reconcile_action`/领域派生独立计算。
3. **oracle 只看输出事实**：新增 acceptance 只比较 `observed.*`、`record.*`、
   `events.*`、`remote.irreversible`、`gate_after_release.state`、`replay.raised`
   等产品/环境事实，不把探针内部标签当正确答案。
4. **发现并修正**：刺激 bounds 初版使用 `left,top,right,bottom`，而生产几何解析
   只接受 Android `[l,t][r,b]`；已改为后者，使 `_list_complete` 真实通过而不是
   被探针格式错误提前拒绝。微信/电话“请求中”必须是独立文本节点，不能拼接在
   槽位标题里，否则生产精确计数不会命中。
5. **发现并保留缺口**：A01 的“输入法变化后重取唯一控件 bounds”“0/多发送候选”
   需要 M6 的控件发现与点击计划；M5 `perform_action` 接收调用方 `tap_points`，
   不自行发现发送控件，因此两项保持 BLOCKED，未伪造。A03/A04 “直接发出版本”
   只有一次不可逆点击，而真实执行器明确要求非文本动作先有可逆槽位点击；两项
   保持 BLOCKED 并记录原因。

## 三、第二轮：持久锁、事务时序与负例

1. **F-B 准入后中断**：真实 `perform_action` 先提交 `begin_action`，再调用
   `bind_action`；在 `bind_action` 抛 `BaseException` 模拟进程死亡，pending 已在
   真实 SQLite 落库。重开同一临时 profile 后再次调用 `perform_action`，真实仓储
   以 `action_conflict` 拒绝且远端不可逆命令为 0。该切点只证明“准入 pending 已
   持久化后中断”，不声称证明真实 OS 进程死亡或设备远端未发生。
2. **F-C 断连**：合成 `Popen.communicate` 在记录第 1 次不可逆 `input tap` 后抛
   `OSError`；产品派生 `unknown`、设备 `quarantined`，重开/重试被真实仓储或门禁
   拒绝且不可逆命令不再增加。合成进程对回收阶段的重入返回既有结果，避免
   `_kill_reap` 二次调用被误记成第二次远端动作。
3. **F-E 完成事务失败**：在真实 `SqliteStore` 的测试故障点
   `action_before_event` 抛 `StoreError("store_io_error")`，`complete_action`
   整体回滚：动作仍 `pending`、事件只剩 `action_pending`、门禁仍 `held`，远端
   不可逆命令保持 1；重试在 `begin_action` 得到 `action_conflict`，不撤销远端。
4. **F-D 原始证据缺失/冲突**：before/after 使用同一原始 XML（或删除缺少邻居
   锚点），产品派生 `unknown/result_unverified`，不把空返回或同快照当成功。
5. **A07 人工收敛**：对真实 pending/unknown 记录调用真实 `reconcile_action`，
   核对持久 IME、原 host、命令停止检查器与本轮显式确认。`confirm_performed`、
   `confirm_not_performed`、`abandon` 分别得到 performed/done、not_performed/
   not_sent、cancelled 且 `lock_retained=true`；`reconnect` 的重放被拒绝且门禁
   仍占用，不自动续发。
6. **A08 真实锁**：六个非法证据案例在真实领域校验之外，统一建立真实 pending
   动作，重开/重试被真实键锁阻止，且不可逆命令为 0；没有只构造 `Evidence` 就
   宣告锁判据通过。
7. **facts CLI 持久回归**：`FactsCliPersistenceTests` 在临时项目根复制 `app/`，
   用真实 `python -m app facts` 与合成 `LOCALAPPDATA`；held/quarantined/unknown/
   排他锁下 set/revoke/forget 均失败，事实行、事件行与原门禁行前后逐字比较不变，
   目标 profile 不创建。`forget` 只核对表内值删除与无值审计，不声称擦除 WAL/
   空闲页。

## 五、独立审核 P1–P9 返修与更正（2026-11-25 第二轮）

本节保留首轮“44 PASS”的原始声明及其后来被独立审核判定为高估的历史，并给出返修后的
可核对状态；不删除上面的原始结论。

1. **P1 A08 改为同一证据闭环**：六个案例都先在同一真实 profile 建立真实 pending
   动作，再把该案例的原始观察经真实 `derive_action_outcome` 或直接构造的非法
   `Evidence` 送入真实 `SqliteStore.complete_action`。`same_snapshot`、
   `missing_snapshot`、`read_ok_no_action_delta`、`screenshot_only` 得到对应
   unknown/not_performed 并真实提交；`performed_none`、`not_performed_sent` 得到
   `invalid_observation`，记录仍 pending、事件仍 1、任务仍 running、门禁 held。
   关闭并重开 profile 后同键重放分别得到 `stale_lease`/`action_conflict`，远端
   不可逆命令为 0。此前“合同层 + 无关 A01 锁”的 PASS 声明不再成立，现已替换。
2. **P2 确认框与跨 kind 授权**：wechat/phone/delete 的 dialog 是独立层级，包含
   确认/取消控件且不等于 before；探针在 dialog cat 时独立读取真实仓储，记录
   `action_state=pending/gate=held` 并断言 `dialog_distinct` 与 `has_confirm`。
   A04 base/confirm_dialog 额外用 change_wechat 授权调用 phone 动作，得到
   `authorization_required`、零点击、无记录。
3. **P3 FB 边界与变异控制**：FB 统一走 `_perform` + `_synthetic_device`，不再
   复制参数表；移除崩溃点后执行同一正常动作，仍只触达合成 Popen（8/13 条合成
   命令），且 `subprocess.Popen` 恢复为基线。不再只依赖 `bind_action` 先抛异常。
4. **P4 过程日志**：perform_action/执行器/reconcile 均注入显式 `ProcessLog`；
   oracle 断言 validate/admit/execute/derive/commit 的 started→终态、
   `action_finish_command`、完整失败分类、唯一 correlation、无动作正文；按
   FA/FB/FC/FD/FE 的早停路径只断言实际出现的阶段，未补造后续阶段。
5. **P5 reconnect**：保留原“锁屏/IME/身份/在途命令/不自动续跑”强判据，但 M5
   没有键屏与会话身份的恢复入口，故变体改回 ASSET_ONLY/未冻结并明确 BLOCKED；
   探针中的部分真实 `AdbRecoveryObserver` 与 `reconcile_action` 观察不作为 PASS。
6. **P6 abandon / confirm_not_performed**：abandon 增加 `gate_after_reconcile`
   仍 held 的断言；confirm_not_performed 在真实重开 profile 后再次调用
   perform_action，断言 `precondition_failed`、零新增不可逆、记录仍 not_performed。
7. **P7 重开与归属更正**：FB/base/FC/FE/A08 均执行真正的 `store.close()` 后
   新建 `SqliteStore` 重放；FB 同时记录同连接重放，明确区分“独立连接可见 /
   同连接重试 / 关闭重开”，不声称跨进程重启。FE 增加任务 running、未 done、
   命令账本闭合、重放前后事件数不变。此前本文件“重开同一临时 profile”的表述在
   首轮代码中并不成立，已在第二轮补实现；`117 = 111 资产/判据 + 6 facts` 的
   归属已更正，M5 探针只在 acceptance 运行。
8. **P8 base 自身重放**：A01–A05 base 各自在完成动作后关闭重开并同键重放，断言
   `precondition_failed`、零新增不可逆、任务 done、事件数不变，不再借用 FB/FE。
9. **P9 清理**：合成 OS 根固定到 `data/evals/m5-probe/os-gate`，手工运行也不在
   仓库根创建 `localappdata/`；修正 facts 投影 docstring、移除死状态、删除
   `locals()` 兜底并统一 FB 参数表。

返修后 M5 结果为 **43 PASS、11 BLOCKED、0 FAIL**（A07 reconnect 如实 BLOCKED），
A08 六项均完成真实 complete_action 闭环；全量 acceptance 仍因 M6–M8、DEVICE 与
其它 ASSET_ONLY/DEFERRED 保持 BLOCKED、退出 3。真实设备/模型/provider 仍未测。
