## 第一轮：按正式缺口与负控修复

实际发现：

1. `m5_probe._log_events` 只是字段投影，oracle 只查 `log_pairs`/correlation/body，
   未断言 `action_finish_command`、失败 `reason_code/error_category`、原始字段
   白名单和附件/坐标/授权 nonce；删掉 finish 或改错分类仍可能 PASS。
2. FE 账本摘要已有 begin/complete，但 oracle 只查 complete/unresolved，未断言闭合；
   FE `gate_after_release` 是测试释放后的 quarantined，缺少 release 前产品现场。
3. `_run_reconcile_case` 的新 `reopened` store 未在 finally 关闭；P5 旧文件存在
   “部分真实恢复观察”和未使用 import 的不实声明。
4. `m4c_probe._gate_race` 只有聚合重试，没有逐次 None/error/row 轨迹、
   attempts/exhausted/最后错误，也没有可持续负控回归。

实际修改/检查：

- 增加 `_log_projection`：从原始 JSONL 独立构造事件、固定字段白名单违规数、
  敏感载荷命中数、finish 计数、失败分类映射；`_attach_log` 输出
  `log_finish/log_reasons/log_schema_violations/log_sensitive_hits`。
- 在 A01–A05 的 base/FA/FB/FC/FE 及 A08/A07 原 oracle 中补实际发生阶段的
  finish/分类/白名单/敏感字段断言；早停路径不补造后续阶段。
- FE 补 `gate_before_release.state=held` 与 `ledger.closed=true`；
  `gate_after_release` 保留为测试清理后的 quarantined。
- `m4c_probe.observe_gate_after_busy` 记录固定类别轨迹、attempts、
  saw_none/saw_io_error、exhausted、last_error、shared_found，总上限 80×25ms，
  acquire 仍只一次。
- 新增 12 个 offline 负控：日志/账本变异由原 A01_FE 判据拒绝；持续 None、
  持续 IO 错、延迟行、第 81 次行、非预期错误传播；实际 loser 投影与 7 个身份
  字段篡改送入原 D09 `children_relation`。

本轮结果：`python -m unittest tests.test_offline_scenarios` 129 项通过；
`--only SC-A` 43 PASS / 11 BLOCKED / 0 FAIL。原始失败与旧声明保留在旧文件和新
交付证据目录，不以最终绿色覆盖。
