# BOSS 离线场景资产 三轮作者自审记录

> 性质：作者自审，不是独立第三方审查，也不是实机、真实模型或产品验收。记录日期 2026-11-24；所有审查输入均为本仓库合成资产与协调端独立复现的合成反例，未读取真实配置、聊天、设备或私有样本。

## 0. 审查范围与当前结论

- 范围：`tests/scenarios/`、`tests/test_offline_scenarios.py`。
- 场景 73 个、变体 313 个：F 291、T 9、O 12、W 1；READY_FOR_APP 64、ASSET_ONLY 227、DEVICE_GATE 22。
- 资产自检：通过（`--mode assets` 退出 0）。
- 严格验收：当前无 `app/`，64 个 READY 全部 `BLOCKED_MISSING_APP`，227 个 `BLOCKED_ENTRY_UNFROZEN`，22 个设备门槛未验收；总体 `BLOCKED`、PASS 0，退出 3。
- 三轮均发现真实缺陷并修订；未发现可以支持“产品已通过”的证据。

## 1. R1 覆盖与独立 oracle

### 发现

1. 初版清单只有 289 个变体，方案中若干明确要求的变体缺失：U06 双方摘要/时间相同、U10 版本不符、U12 缺身份字段、U15 已验证全局零但另有正信号、D05 包大小/编码/链接/联系方式冲突、D09 TTL/read_only 占用、D10 base 不匹配/旧验收失效、D11 provider 错误、M5 简历请求与交付、微信/电话确认框与直接发送、文本输入法/发送控件、M7 keeps_contact/仅模型 rejected、C03 目录 IO 失败。
2. 严格比较器把 Python `True` 与 `1` 视为相等；`stdout_json_equals`、路径 `equals` 与 `in` 都可被 bool 冒充整数绕过。协调端用纯合成输入独立复现。
3. `compare_invocation` 对 `stdout_json_ok=false` 仍可返回无差异；普通业务 CLI 的非 JSON/非对象输出没有强制失败。
4. `replay_events` 忽略脚本 `clock_start_ms`，首条负数时间未被校验；`VirtualClock(5000)` 与首事件 1000 会产生 end<start 却不报错。

### 修订

1. 作者脚本补齐上述变体；变体从 289 增至 313，READY 64、ASSET_ONLY 227。
2. `compare.strict_equal` 按 JSON 类型严格比较，bool 与整数、null 与缺失互不相等；路径 `equals`/`in`/`type`/`length_equals`/`keys` 全部严格化。
3. 普通 CLI 必须是单个 JSON 对象；帮助等非 JSON 只能显式 `allow_non_json_stdout` 并要求非空 stdout，不能放宽业务输出。
4. `validate_script` 校验起点为非 bool 非负整数、事件与时刻不早于起点；注入时钟当前值必须等于起点；`replay_events` 拒绝回拨。

### 复验

- `python -m unittest discover -s tests -p test_offline_scenarios.py`：bool≠int、非法 stdout、null 键存在、键集合/长度、时钟起点/负值/回拨反例全部通过。
- 合法 S01 脚本复验 `arrival=8000`、`first_observed=10000`、`handling_started=20200`、`waited_ms=10200`；缺失 handling 保持 null。
- 资产自检 73/313，milestone 计数与方案一致；每个变体都有独立 expected 且 `expected_ref` 指向自身。

## 2. R2 故障、安全与跨模块一致性

### 发现

1. `_validate_sensor_manifest` 虽返回 `../` 越界错误，之后仍可能解析外部 XML/读取外部 profile；`_validate_fixture_files` 在路径错误后仍继续读取。
2. `load_json` 的异常消息含 OSError 原文；`runner.main` 未兜底，CLI 可输出 Traceback 与绝对临时路径。
3. `_db_check` 用 `str.startswith` 判断隔离根，同名前缀兄弟目录可逃逸；SQLite 连接可能创建/写入文件。
4. `_prepare_isolation` 的 `copytree(symlinks=False)` 会跟随未验证链接复制外部内容；只遍历子项、未检查 app 自身及父路径 junction。
5. `_isolation_env` 继承几乎全部宿主环境，可能把模型/服务凭据带给 SUT。
6. 畸形 manifest（如 `xml_paths=[{}]`）在去重处 TypeError，绕过受控资产错误。
7. `_prepare_isolation` 复制整个 fixtures 树，`m2/sensor/*/expected.json` 随输入进入 SUT 隔离根，等于把正确答案放到被测进程可读位置；协调端用合成 manifest+expected 独立复现。
8. 改为只复制选定输入后，SC-C02/config_missing_file 的故意缺失配置被隔离层提前拒绝，产品应返回 invalid_config 的错误处理没有被验收。

### 修订

1. 所有 manifest/fixture 路径先做相对、symlink、解析后边界校验；任一非法立即返回，不读取。XML/profile 只在全部路径合法后解析。
2. `load_json` 只保留相对文件名与异常类别；CLI 在资产加载与执行外层捕获异常，输出固定安全 JSON，禁止 traceback、异常链与绝对路径。
3. `_db_check` 使用 resolve 后 `relative_to`，先拒绝 symlink 与越界，再 `exists`/`sqlite3.connect(mode=ro)`；同名前缀兄弟反例 spy 证明 connect 0 次。
4. 复制前递归扫描 app 与 fixtures 全树，拒绝 symlink/junction/越界；检查 app 自身与到目标根的父路径。本机 Windows junction 可创建，实际反例通过。
5. 环境改为最小白名单；本地应用数据、TEMP、PATH、PYTHONPATH 与 tripwire 日志全部落在隔离根；合成凭据变量反例不再继承。
6. 先逐项类型检查再 `set()` 去重；8 类畸形形状均返回受控错误，无 TypeError。
7. 隔离只复制步骤/manifest 选定的合成输入文件，显式排除 `expected.json`、`oracles.json` 与 `expected.*`；未引用案例不复制。补“选定输入存在、expected 与未引用案例不存在”的反例。
8. 变体显式登记 `expected_missing_inputs`（仅固定相对路径）；只有这些缺失输入允许交给真实 CLI，父目录与边界仍校验；未登记缺失仍阻断。资产校验还拒绝“登记缺失但实际存在”。

### 复验

- 越界 manifest spy：只读取 manifest 自身，外部 XML 解析与 profile 读取均为 0。
- 选定输入复制：manifest/profile/XML 进入隔离根，`expected.json` 与未引用案例均不存在。
- 同名前缀 sibling 与 symlink：拒绝发生在 exists/connect 前；`mode=ro` 合法库 `user_version` 断言通过。
- 实际 junction 反例：`_validate_source_tree` 在复制前拒绝根/父路径 junction。
- tripwire 子进程：`socket.socket.connect(None, ...)` 与 `subprocess.Popen([])` 均被拒绝并记录；即使 tripwire 失效，receiver/argv 也不足以发起真实网络或进程，测试因此不会产生外部动作。断言 RuntimeError 与 tripwire 类别以区分 API 参数错误。
- 限制：Windows 普通 `os.symlink` 当前账户不可创建，symlink 分支主要靠判定分支与 junction 实机反例；未构造完整 OS 沙箱，不宣称恶意 app 隔离。

## 3. R3 测试真实性、副作用与文档一致性

### 发现

1. 资产自检通过容易被误读为产品通过；缺 app 时必须显式阻塞，不能零项/全 skip 报 PASS。
2. 验收报告可能写入仓库可见路径；隔离根、临时库与报告应只落在被忽略的 `data/evals`。
3. README/AGENTS 初稿的计数、子目录说明和待同步根索引可能落后于生成结果。
4. 现有 `npm test` 52 项是原评测链路自检，不是新增业务覆盖。

### 修订

1. `acceptance` 先 `validate_assets`；失败返回 `BLOCKED_ASSETS` 且 `results=[]`，不运行 SUT。缺 app 时 PASS=0、总体 BLOCKED、退出 3，`product_acceptance` 永远不是 PASS。
2. 报告写 `data/evals/scenario-runs/<run>/report.json`；隔离根与临时库同在其下；未修改 `.gitignore`，未提交报告。
3. README、目录指南统一使用 73/313/F291/T9/O12/W1、READY64/ASSET_ONLY227/DEVICE_GATE22；明确测试资产与产品验收分流。
4. `npm test` 仅作为现有链路回归记录，不计入场景覆盖。

### 复验命令与结果

```powershell
python tests/scenarios/tools/build_assets.py

python -m unittest discover -s tests -p test_offline_scenarios.py
python -m tests.scenarios.framework.runner --mode acceptance --target .

```

- 生成：成功；catalogue/oracles 与夹具重建。
- 资产自检：退出 0；73 场景、313 变体；无资产错误。
- unittest：42 项通过，含 1 项条件分支；junction 实际反例在本机执行；tripwire 反例使用 None receiver 与空 argv，即使补丁失效也不产生外部网络/进程。
- 严格验收：退出 3，`overall=BLOCKED`、PASS 0、FAIL 0；64 BLOCKED_MISSING_APP、227 BLOCKED_ENTRY_UNFROZEN、22 DEVICE_GATE_UNVERIFIED。
- `npm test`：52 通过；仅现有链路回归。
- `git diff --check`：无空白错误。
