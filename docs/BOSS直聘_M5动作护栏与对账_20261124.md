# BOSS直聘 M5 动作护栏与人工对账设计事实（2026-11-24）

本文记录 M5“不可逆动作护栏”的已实现边界、持久化迁移、授权/额度/证据规则与离线验收方式。所有命令、合成夹具和测试都不连接真实手机、ADB、模型或网络，也不构成发送授权或完整 MVP 验收。

## 1 范围

M5 只交付五类不可逆动作护栏：

| 动作 | 动作键 | 前置 | performed 效果 |
|---|---|---|---|
| 发文本 | `boss:<message_key>:reply` | 正文回读一致、本轮分动作授权 | `sent` |
| 发简历 | `<conversation_key>:resume` | 附件名匹配 | `request_sent`；仅“附件简历已发送”才 `sent` |
| 换微信 | `<conversation_key>:wechat` | 槽位可点击且未处理 | `request_sent` |
| 换电话 | `<conversation_key>:phone` | 同上 | `request_sent` |
| 删会话 | `<conversation_key>:delete` | 身份唯一、目标存在、保护项为空 | `deleted` |

`conversation_key` 为已含应用前缀的 `boss:conv:<64hex>`；`message_key` 为 M3 稳定消息键 `boss:msg:<64hex>`。因此文本动作键精确形如 `boss:boss:msg:<64hex>:reply`。M6 职位沟通会复用同一 pending/授权/不重放协议，动作键为 `boss:<job_key>:apply`，本阶段不实现。

统一流程：原子写 `pending` 与唯一动作键锁 → 执行一次 → 由可信前后观察推导三态 → `unknown` 或现场未收敛的 `pending` 标 `blocked` 并隔离设备 → **绝不自动重试**。`cancelled` 只由人工 `abandon` 产生，不代表 Evidence 成功或未执行，也不解除动作键锁。

## 2 持久化与迁移

profile 库从结构版本 1 最小演进到 2，`profile_meta.schema_version` 仍表示事实/身份 schema 1，SQLite `PRAGMA user_version` 表示完整结构版本。v2 在 v1 八表（M1 五表 + `profile_meta/profile_facts/profile_fact_events`）之上追加：

- `action_records`：动作键主键、动作类型、任务/目标/会话、`pending/performed/not_performed/unknown/cancelled`、三态与效果、原因、前后快照、现场收敛标志、授权摘要、原租约 owner/pid/host/nonce/截止时间、时间。
- `action_events`：`action_pending/action_completed/action_reconciled`，不含正文、坐标或授权原值。
- `action_ime_state`：切换输入法前持久化的原 IME、当前 IME、恢复标志，重启可读回。

迁移只接受“用户对象集与 v1 模板逐项一致且 `user_version=1`”的 profile 库：先用标准库 SQLite backup API 写不覆盖的 `runtime.sqlite3.v1-backup-<uuid>.sqlite3`，再在单个 `BEGIN IMMEDIATE` 事务内追加 v2 表/索引并更新版本。备份或迁移失败保留原 v1 库；普通 M1 五表库、额外对象、未知版本、错误 profile 身份一律拒绝，不宽放、不导入旧合成库。

## 3 授权与准入

- 本轮授权 `ActionAuthorization` 绑定 profile、base/pack 摘要、验收 base/pack 摘要、任务键、精确动作键、允许的动作类型集合、截止时间、显式确认和随机 nonce。
- 文本授权不能覆盖附件、联系方式或删除；授权缺失、种类不符、动作键/任务不符、摘要漂移、未确认、`expires_at <= now` 均拒绝。
- 每个动作执行前复核当前包/base、当前验收、profile/任务/共享租约和授权 nonce；任一漂移不调用执行器。
- CLI `action perform` 只接受 `draft_only`，且必须同时给出 `--confirm-device`、`--confirm-action` 与至少一个 `--authorize`。`auto_send_tier_a` 保持不可用；合成授权通过不代表真实 A 档可用。

## 4 唯一文本额度与冷却护栏

额度直接由 `action_records` 计算，不另建调度计数或内存状态机：

- 日额度：profile 的 UTC 日期内跨 app 合计 `action_kind=send_text` 且 `state=performed`、`effect=sent` 的记录。附件 `sent/request_sent`、`not_performed`、`unknown` 不充当成功文本。
- 冷却：按 profile/app/会话取该会话最近一次成功文本的 `observed_at + reply_cooldown_seconds`；`now < 截止` 拒绝，`now == 截止` 允许。
- 任一文本 `pending/unknown` 先阻断新发送；不把 unknown 当未发送。
- 额度/冷却检查与本次 pending、唯一动作键锁在同一 `BEGIN IMMEDIATE` 事务内完成，防止并发重复准入。
- 换包、restore、重启、调低额度都不清零历史成功记录；已达新上限即停。库不可读或缺少动作表时返回固定仓储错误，不返回“已用 0”。

M08 的合成资格正例通过 `action eligibility` 独立计算：有效本轮授权 + 无已发送/未决 + 未到冷却 → `eligible=true`，同时 `policy_tier="C"`、`production_auto_send=false`、`actions_performed=0`。

## 5 证据与现场收敛

`Evidence` 仍是既有七字段与 `performed/not_performed/unknown` 三态、固定 effect 词表。执行器返回的是观察，不是 Evidence；`derive_action_outcome` 只在以下条件同时成立时给出 `performed`：

- 前后快照 ID 都非空且不同；
- 动作特有变化成立：文本新增回显且正文回读一致、简历附件名匹配且观察到请求/交付、联系方式槽位变“请求中”、删除目标由存在变不存在且锚点仍在；
- 删除目标“早已不存在”或有变化无关都不证明执行。

断连分阶段：未点击时 `not_performed`；点击后断连/异常/坏观察为 `unknown`。已证明未点击但输入框不空、确认框仍打开、IME 未恢复或在途命令未退出时，保持 `pending` 并保留共享隔离，不得仅凭 `not_performed` 释放门禁。确认框已打开未确认保持 `pending`。

## 6 人工卡与受控恢复

`pending/unknown/cancelled` 动作生成固定人工卡：

```json
{"task_id":"<任务键>","action_key":"<动作键>","reason_code":"<unknown 原因>","snapshot_ids":["<uuid>"],"allowed_resolutions":["confirm_performed","confirm_not_performed","abandon"]}
```

- `confirm_performed` / `confirm_not_performed` 需要本轮显式确认、当前证据（观察时间等于本次 `now`）、动作键匹配、原命令停止（本机停止检查器）、现场/IME 收敛。成功文本经 `confirm_performed` 只计一次额度。
- `abandon` 只把任务置 `cancelled`，动作记录置 `cancelled`，保留未决动作锁与共享/ profile 设备隔离；之后 `action card`、`restore`、`run check` 仍视为未决。
- 恢复必须在原 profile 与原库身份下，通过共享门禁 `recover` 受控接管：要求明确 `--confirm-recovery`、原 profile/原库绑定一致、显式确认与原持有 PID 已停止。正常 `acquire`、TTL、PID 消失或换新 profile 都不会自动解锁。
- 原 IME 在切换前写入 `action_ime_state`；恢复命令失败或最终读回不一致时保持未恢复，不能假称已恢复。

## 7 CLI 离线入口

```powershell
python -m app action perform --profile demo --pack prompts/local/demo --mode draft_only `
  --action-kind send_text --target-key <message_key> --seed-fixture <合成未读夹具> `
  --fixture <合成动作脚本> --credential <data/evals/.../acceptance.json> `
  --provider <provider_id> --model-id <model_id> --model-config-hash <摘要> `
  --authorize send_text --confirm-action --confirm-device
python -m app action eligibility --profile demo --pack prompts/local/demo --mode draft_only `
  --action-kind send_text --target-key <message_key> --conversation-key <conversation_key> `
  --task-key <task_key> --credential <凭证> --provider <provider_id> --model-id <model_id> `
  --model-config-hash <摘要> --authorize send_text --confirm-action
python -m app action card --profile demo
python -m app action reconcile --profile demo --pack prompts/local/demo --mode draft_only `
  --action-key <动作键> --resolution confirm_performed --fixture <合成对账脚本> `
  --confirm-action --confirm-device --confirm-recovery
```

`perform` 的合成执行器只回放观察，不接收 Evidence；它经过同一生产用例、仓储边界与三态推导。`reconcile` 的合成脚本同样只提供观察，当前证据时间由 CLI 观察边界填充。CLI 不提供真实设备动作入口；`app/adapters/adb/actions.py` 的真实 ADB 原语仅由 mock subprocess 测试，使用参数数组、`shell=False`、5 秒有界超时、每条命令前共享门禁复核且不重试。

## 8 第1轮审核返修（G01–G10）

- G01：动作键由唯一 `action_key_for` 与实际消息/会话目标重算比对；动作入口核对实际 `SqliteStore.profile_id/path`、固定原库路径与共享门禁身份，不只比较调用方字符串。
- G02：`perform` 在写 pending/设备调用前要求实际 `running`；`begin_action` 后 IME 读取前、每条 ADB 命令前、执行后提交前统一 guard 重读当前 base/pack、当前验收、任务租约、共享身份、授权期限/nonce；漂移保留 unknown 且不重放。
- G03：真实适配器先验证唯一身份、列表完整/保护项、编辑器正文回读、附件名、联系方式槽位，再发不可逆点击；只对目标节点前后新增差分判定；既有提示、坏 XML、同内容快照不证明执行；删除要求目标消失+锚点仍在。
- G04：坏观察/执行中异常在同一已尝试动作边界收敛 unknown/暂停并保留卡；公开结果 `evidence` 返回完整七字段；确认框未关也参与 performed 暂停判定。
- G05：恢复核实际 store/profile/原库、原 host、持久化原 IME 与原父子命令停止检查器；生产默认父子命令检查器 unknown，不用单 PID 猜测解锁；成功后事务更新 IME restored。
- G06：`abandon` 仍只关任务并保留锁/隔离；之后可对 cancelled 动作受控 `confirm_performed/confirm_not_performed` 清锁，但任务保持 cancelled、不重开。
- G07：完成证据时间必须落在本次 pending 与提交 now 之间；资格同时检查同一动作历史，已 sent/pending/unknown 分别返回 `action_conflict`/`text_send_blocked`，不重复准入。
- G08：指定 IME 在输入前实际切换并读回，失败不输入；动作后恢复原 IME 并读回，成功完成/对账事务把唯一 IME 账本置 restored。
- G09：`perform_action`/`reconcile_action` 显式日志记录 validate/admit/execute/derive/commit 与 reconcile 成对阶段；ADB 动作命令使用 `adb_action_dump/cat/input/tap/ime_get/ime_set` 有限标签，不写参数/serial/正文/路径。
- G10：删除重复 `_verify_existing`，只保留 `_verify_objects`；ADB 子进程/门禁/超时/证据落盘收敛到共享 `command.py`；补 `simulated/__init__.py` 文件用途、测试 hook docstring、activity 现状说明；同步受影响指南与 operator。

## 9 第2轮审核返修（H01–H07/N01）

- H01：公开 `perform_action` 默认时钟改为动态 `utc_now`；guard 使用当前 base/pack 与当前验收 base/pack 四摘要，任一漂移在下一条命令前拒绝。
- H02：执行后共享/租约/验收/包失效不再依赖正常 complete；仓储 `freeze_attempted_action` 在原 owner/nonce/任务身份下允许过期但拒绝新身份，原子置动作 unknown、任务 blocked、设备 quarantined、写事件与卡；不重放。
- N01/H07：`complete_action`、`begin_action`、`require_running`、`current_lease_expiry` 复用同一当前租约核验，使用同一已核验行的真实截止；合法 `renew` 后旧捕获 Lease 仍可完成，过期/nonce/owner/host 不符仍拒绝。Evidence 投影只保留仓储唯一返回；pause 条件合并为一处。
- H03：适配器锁定唯一姓名+职位目标、唯一 EditText 精确回读、非滚动完整列表、保护项、可点未处理联系方式槽位；同一目标子树前后新增差分；单 tap 非文本计划、无关子树提示、既有状态、同名重复均不证明执行；删除要求目标消失且锚点仍在。
- H04/H05：共享门禁受控接管要求同 host；生产命令停止检查器同时检查原父 PID 与直接子进程，无法枚举时 unknown；完成观察原 IME 必须匹配持久原值，缺失/不同值不收敛且不写 restored；IME 在无需设备改变的前置之后才切换，切换后早退/异常有界恢复并读回。
- H06：门禁/guard 失败使用 `adb_gate/action_guard` 白名单类别；reconcile commit 成对 started/终态；可选证据目录保存 before/readback/dialog/after 原始 XML 与内容 UUID/动作索引，保存失败不假称成功。
- H07：删除重复 schema verifier、Evidence 投影与租约核验；共享 ADB 子进程边界保留；受影响指南/operator 同步。

## 10 第3轮审核返修（I01–I06）

- I01：guard 要求当前快照 base/pack 与验收 base/pack 四字段均存在且为 64hex；缺字段、None、坏类型不再回退成包摘要，后续命令前拒绝。
- I02：`ActionPlan.identity_labels` 支持姓名+职位等复合身份；before/readback/dialog/after 各阶段核对同一目标；文本只认可目标子树内唯一 editor；联系方式要求对应类型 `enabled=true`/`clickable=true` 且未处理；简历确认同时核对目标与附件；删除确认阶段重核目标/保护，前后均要求显式非滚动完整覆盖。
- I03：`CommandIdentityStore` 按动作保存 ADB 命令 PID；`default_command_stop_checker` 检查父与直接子，恢复 CLI 对已记录命令 PID 逐个核验；新增 `AdbRecoveryObserver` 一次有界读取层级/IME，复用于生产恢复接线。
- I04：已切换 IME 后的输入非零/超时/回读失败统一进入一个有界原 IME 恢复并读回；恢复失败保持隔离且原命令不重发。
- I05：同一真实阶段只记录一次 started 和一个终态；提交失败转冻结使用独立 `action_freeze` 阶段，reconcile 的 validate/commit 不重复终态。
- I06：动作层级 dump/cat 与证据保存复用 `AdbScreenReader`，动作层只追加相位/UUID 索引；`_match_lease` 收敛到唯一 `_match_current_lease` 身份本体并保留 M4c 捕获截止语义。

## 11 已验收边界与未测项
已用真实临时 profile 库、公开生产 API 与实际 CLI 组合根验证：合成候选入库 → claim → start → 共享占用/当前验收/本轮分动作授权 → 原子 pending 与唯一键锁 → 一次合成执行器 → 动作特有观察 → Evidence → 任务/动作/审计一致提交；五动作正例与拒绝反例、pending 先落库、重复键/并发、未知不重放、abandon 不解锁、额度跨 UTC 日/边界/调低/重启、迁移备份与故障回滚均有可运行测试。

明确未测：真实手机、真实 ADB 命令输出与坐标/输入法差异、真实模型/provider、真实私有数据、M6 调度/职位沟通、M7 清理、M8 模式与完整 MVP。合成授权、公开评测凭证与本文的任何 PASS 都不构成真实发送、设备或模型授权。
