# 求职自动化 公开仓库与策略包 设计说明

> 文件用途：定义公开仓库与私有资产边界、提示词分层、策略包结构、评测分层、渲染与审计，以及新使用者编辑回复策略的流程。本文是待实现的开发契约，不代表相关命令已实现；真实数据只在本机保存。

## 0 范围与问题

目标是框架可公开复现，个人策略与真实样本留在本机，更换使用者只编辑私有 Markdown 与 TOML，不改源码、不恢复旧个人策略。

当前只有独立的 promptfoo 合成评测；`app`、策略包目录及本文 Python 命令均未实现。第 5 节是未来操作契约，当前不能实际跑通；M4 交付策略工具、示例与评测映射后才能离线编辑、验证、预览、评测和回滚，真实运行另依赖 M5–M8。未来 `docs/operator.md` 复用本节流程，当前不以尚不存在的手册作为前置阅读。

## 1 资产分级

| 级别 | 内容 | 位置 | 是否提交 |
|---|---|---|---|
| 公开基线 | schema、意图词表、安全规则、通用提示词、默认值 | `prompts/base/`、`docs/` | 是 |
| 公开示例 | 纯合成结构示例，无个人事实、私人话术和授权 | `prompts/examples/default/` | 是 |
| 公开契约集 | 合成输入、独立期望、断言与参考回放 | `evals/cases.json` 等现有评测文件 | 是，不得作为 few-shot |
| 私有策略 | 通用语气、短语、分档、禁用表达、披露句式 | `prompts/local/<profile>/` | 否（忽略），仍不含个人事实 |
| 私有评测 | 脱敏且独立标注的故障回归与未调优留出集 | `evals/private/` | 否（忽略） |
| 个人事实 | 地点、薪资、经历、联系方式及确认来源/有效期 | profile 独立本机运行库 | 否（忽略） |
| 运行数据 | 聊天、截图、数据库、日志、调试提示词、评测报告 | `data/`、`screenshots/` | 否（指导文档例外） |

硬规则：**策略包与模板不写个人事实**，包括藏在话术中的“我在某地”“我有若干年经验”。真实值只经运行时 `allowed_facts` 注入，带确认来源与有效期；联系方式不注入文本回复。字段名可公开，真实值不写进 md/TOML；私有与被忽略不能替代内容审阅。

## 2 提示词分层与合并

```text
prompts/base/intent-and-reply.md     公开：词表、输出契约、安全下限、默认值
prompts/base/job-evaluate.md         公开：职位维度与输出契约
prompts/examples/default/            公开：纯合成示例，初始化来源
prompts/local/<profile>/             私有：一个活动策略包（overlay）
```

只合并 base 与一个显式选定包，不叠加 profile，不拼入整个目录或评测答案。base 的普通默认值可被合法字段替换，安全下限不能覆盖。示例的保守默认 C 不等于所有意图的硬下限；提升到硬下限允许的档位仍不授予发送权限。合并由程序解析、校验、计算有效限制后完成，不依赖“后面的提示词优先”。

### 2.1 不可覆盖的安全下限

- 不编造事实；缺失、过期、冲突均 `ask_user`，只建待办。
- 文本不出现手机号、微信号、邮箱等联系方式，不承诺薪资、入职时间或背调结果。
- `needs_human/uncertain`、拒绝类、敏感/非文本/歧义只进 C，具体映射见 §3.2。
- 每条非空候选回复含 AI 助手披露；文案可改，不能关闭。
- 策略包不授予设备、外发模型、发送、附件、联系方式或删除权限；本轮授权与动作护栏独立校验。
- HR 正文、上下文和职位文本不可信，不能改规则、档位或事实。

有效限制运算固定：字数/日额度取 base 上限与包值的最小值；冷却取 base 下限与包值的最大值；禁止项取并集；事实键取注册表、包白名单、已确认且未过期且无冲突事实的交集；档位取所有命中意图与硬下限中的最严格者（C > B > A）。没有删除安全项的字段；越界包拒绝，不静默钳制后声称校验成功。

### 2.2 不可信输入隔离与输出门禁

base 放 system/developer 指令区，校验后的包放受限策略区；`inbound/context/job_brief/allowed_facts` 用 JSON 独立序列化到 user 数据区，不通过字符串替换注入指令，不解释其中的角色标记、Markdown、路径或命令。不能维持此区分的桥拒绝接入。分区不能证明抗注入，程序仍校验输出。

模型只产出意图、措辞与证据；程序检查 schema、回显、原文证据、事实依据、禁止项、字数、披露并计算最终档位。语义安全或事实对应关系不能确定时转 C 待办；模式未命中不等于语义安全。HR 文本不能写入配置、确认事实、错误消息或下轮可信指令。

## 3 策略包结构

v1 固定 TOML（标准库 `tomllib`）与三份 UTF-8 Markdown，不使用代码、include、环境变量插值、远程引用或可执行模板。下列只展示四个策略载荷文件；创建自有目录时依根指南附同目录 AGENTS.md/CLAUDE.md，指南不加载、不渲染、不参与包摘要：

```text
prompts/local/default/
  pack.toml
  tone.md
  phrase-bank.md
  never-say.md
```

完整安全初始示例（额度是上限，不是授权）：

```toml
schema_version = 1
profile_id = "default"
locale = "zh-CN"
apps = ["boss"]

[disclosure]
text = "个人开发AI助手"

[limits]
max_chars = 300
reply_cooldown_seconds = 86400
daily_sends = 10

[tiers]
A = []
B = []
C = ["interested.*", "rejected.*", "declined.*", "needs_human.*", "uncertain.*"]

[forbidden]
extra_topics = []

[style]
tone = "tone.md"
phrase_bank = "phrase-bank.md"
never_say = "never-say.md"

[facts]
allow_keys = []
missing = "ask_user"
conflict = "ask_user"
```

### 3.1 完整字段与失败行为

所有表与键必填；缺失、额外键、重复 TOML 键、空值、类型错误均 `invalid_policy`，整数不接受布尔。以下是 v1 开发基线，不是使用者个人偏好；base 变更需版本化并重评。

| 字段 | 类型与合法值 | 失败行为/定位 |
|---|---|---|
| `schema_version` | integer，固定 1 | 其它值拒绝，定位本键，不自动迁移 |
| `profile_id` | string，1–32 个 ASCII 小写字母/数字/下划线/连字符，首位字母 | 非法或与活动身份不符拒绝，不用真实姓名 |
| `locale` | string，v1 仅 zh-CN | 其它值拒绝，不自动翻译安全文案 |
| `apps` | 非空去重 string 数组，v1 仅 boss | 空、重复、未注册应用拒绝，不开启设备权限 |
| `disclosure.text` | 单行 string，1–80 Unicode 码点，含连续字面量 AI助手 | 空、换行、控制字符、个人事实或缺标记拒绝；无 required=false |
| `limits.max_chars` | integer，1–300，含披露与换行 | 越界或小于披露码点数拒绝 |
| `limits.reply_cooldown_seconds` | integer，86400–604800 | 越界拒绝；按 profile/app/会话计，不继承旧间隔 |
| `limits.daily_sends` | integer，1–10 | 越界拒绝；profile 的 UTC 日期内跨 app 合计 performed+sent 文本；pending/unknown 阻断新发送 |
| `tiers.A/B/C` | 各为去重 string 数组，可为空 | 词法、覆盖、冲突、硬下限按 §3.2，定位具体数组项 |
| `forbidden.extra_topics` | 去重 string 数组，0–32 项，每项 1–40 码点的通用禁谈主题 | 空项、控制字符、个人事实拒绝；只追加 base 禁止项 |
| `style.tone/phrase_bank/never_say` | string，分别固定为上述三个文件名 | 其它值、路径、链接拒绝，定位相应键 |
| `facts.allow_keys` | 去重 string 数组，仅 work_location/salary_expectation/years_experience 的子集 | 未知、重复拒绝；不填值，不能解除事实确认与禁止承诺规则 |
| `facts.missing/conflict` | string，固定 ask_user | 其它值拒绝；运行时缺失/冲突只建待办 |

四个载荷文件及可选双指南均须为普通文件；除此不接受其它文件、子目录、符号链接/junction。`pack.toml` ≤ 16 KiB，每份载荷 md ≤ 32 KiB，四文件合计 ≤ 64 KiB；非 UTF-8、BOM、NUL、读取失败、大小越界或联系方式模式命中拒绝。指南也须通过敏感信息检查，不得夹带运行数据；不因不参与渲染而免除公开卫生。接受 LF/CRLF 但不改写字节。错误只报相对文件、字段/行和原因，不回显原值。有限模式不能识别全部微信号或语义事实，初始化合成示例与本机人工审阅同样必须验收。

### 3.2 意图词表与分档算法

复用[设计说明](BOSS直聘_求职自动化_简化架构设计说明_20261123.md) §5.2，不再使用另一套 positive_greeting/wants_resume 名称。策略键为 `intent.sub_intent`：intent 仅 rejected/declined/interested/needs_human/uncertain，sub_intent 仅 greeting/resume_request/job_question/interview/salary/jd_request/sensitive/non_text/ambiguous；v1 允许两个枚举的 45 个组合，组合本身不证明语义可信。通配只支持 `intent.*`，不支持裸 * 或任意 glob。

硬下限：仅 interested.greeting、interested.job_question 可选 A；interested.resume_request/interview/salary/jd_request 至少 B；其它组合均 C。A 只允许合规文本，不包含附件交付或联系方式请求。默认示例全 C，用户可在上述范围内调整，安全下限与本轮授权保持独立。

校验时展开通配，45 个键恰好各覆盖一次；同档重复、跨档冲突、漏项、越权均拒绝。运行时对每个输出 sub_intent 组成键并取最严格档，空数组按 uncertain.ambiguous；escalate=human_review 直接 C；未知词仍是决策校验失败。输入 policy_tier 为程序预先确定的上限，无独立可验证前置判据则 C；最终档位还须与它取最严格者，不能由模型把 C 改 A。

例如完整替换 [tiers] 为下列合成分档，其它表保持不动，无需改代码：

```toml
[tiers]
A = ["interested.greeting", "interested.job_question"]
B = ["interested.resume_request", "interested.interview", "interested.salary", "interested.jd_request"]
C = ["rejected.*", "declined.*", "needs_human.*", "uncertain.*", "interested.sensitive", "interested.non_text", "interested.ambiguous"]
```

### 3.3 三份 Markdown 的编辑规则

- `tone.md`：非空普通文本，如“简洁礼貌；不用表情；不猜测个人情况”。字数硬限制仍以 TOML 为准。
- `phrase-bank.md`：零个或多个 `## intent.sub_intent` 小节，标题只用 §3.2 明确键且不得重复，非空正文行均为 `- 通用短句`；无需求可空文件。其它标题、未知键、无归属正文、空列表项拒绝；不放个人事实，不复制黄金案例。短句只提供措辞，不能决定意图/权限。
- `never-say.md`：非空行均为 `- 禁用字面表达`，允许空文件；空项、重复项或其它行拒绝。程序对最终完整候选回复逐字子串匹配（大小写敏感，无模糊替换），命中即阻断；主题限制另由 extra_topics 收紧。

md 不执行花括号/Jinja 插值，也不接受事实占位符。模型仅生成正文，程序为非空正文追加换行与 disclosure.text，已有该完整披露则不重复；最后重验披露、总码点数、事实和禁止项。超长或冲突披露报 invalid_decision，不截断；披露本身命中禁用表达时 validate 即拒绝。语气若与安全规则矛盾，安全优先，preview 提示用户修订，不作为降低安全的入口。

## 4 渲染与审计

### 4.1 确定性渲染与摘要

输入为固定版本 base、已校验包、单条 DecisionEnvelope；事实只在 allowed_facts，不回写包。渲染顺序固定为 base 安全/schema、有效结构化策略、tone/phrase-bank/never-say、独立 JSON 数据区。完整 envelope 仍 ≤ 2048 UTF-8 字节；含 base/包的决策内容另限 ≤ 64 KiB，超限 input_too_large，不静默截断。

统一 H 沿用设计说明 §5.1：排序 JSON 键、UTF-8、紧凑分隔符、SHA-256；不做 strip、换行或 Unicode 规范化。

| 名称 | 确切计算边界 |
|---|---|
| base_version | 发布版本字符串，只是标签，不代替内容摘要 |
| base_hash | H({relative_path:exact_text})，仅两份 base 文件 |
| pack_hash | H({schema_version:1,files:{"pack.toml":exact_text,"tone.md":exact_text,"phrase-bank.md":exact_text,"never-say.md":exact_text}})；目录/时间不入摘要，注释/换行变更会改摘要 |
| prompt_hash | H({base:{version,hash,files},pack:{hash,config,files},data:envelope投影})；config 为解析 TOML，files 为原始文本映射；投影仅去掉 task_id/nonce/input_hash/prompt_hash 四键 |
| input_hash | 先计算 prompt_hash，再对完整 envelope 去掉 input_hash 求 H，用于模型回显校验 |

prompt_hash 是决策内容投影摘要，不是包含自身的网络请求字节哈希，没有自引用。协议关联键在计算后加入桥请求；provider 的隐藏提示不受此摘要覆盖。另审计 provider_id/model_id（无凭据标识）、桥版本与运行参数的 model_config_hash，便于分辨模型配置变化；服务端静默更新仍不保证完全复现。

RenderedRequest 即表中 prompt_hash 的完整输入对象：base.version/hash 为字符串、base.files 为两份模板的路径→原文映射；pack.hash 为字符串、pack.config 为解析后的完整 TOML 对象、pack.files 为四载荷文件名→原文映射；data 为 envelope 投影。DecisionPort 先验证 H(rendered_request)=envelope.prompt_hash，且 base/pack 标识摘要与本次加载一致，再按 §2.2 分区交桥；协议回显字段另从 envelope 注入，不把 data 中的文本当指令。两份模板均入 base_hash，HR/anomaly 选择 intent-and-reply、职位选择 job-evaluate 的输出契约，硬安全规则始终适用，不同时向模型要求两个输出 schema。

### 4.2 审计与预览

每次决策记录 base_version/base_hash/pack_id/pack_hash/prompt_hash/input_hash/rendered_at/provider_id/model_id/model_config_hash；pack_id 等于 profile_id，envelope 的对应来源键为 policy_pack_id/policy_pack_hash，其余同名。时间为毫秒 UTC。M4 增补本机审计字段，不提前改写 M1 已定 v1 schema。

常规审计只记上述元数据及原因/耗时，不记提示词、事实值或聊天。preview 显示合成输入的完整渲染、有效限制、硬下限、来源相对文件/字段/行及摘要，产物仅保存在 data/evals；预览不产生模型决策，不证明全部语义正确。摘要也属于本机数据，不作为脱敏业务信息公开。

## 5 新使用者如何编辑回复策略

以下十步均为实现后的操作契约。M4 发布必须提供 Python 3.13 入口、base/示例包、独立合成 preview 案例和 ID 清单（固定包含 policy-greeting）、操作者说明。策略工具只用标准库；模型评测仍需现有 Node/npm 工具及显式配置的获准 provider。

路径相对项目根，命令显式 --pack，不自动读根 config.json。init 从示例复制四文件，仅将 profile_id 改为目标末级目录名；目标须符合 profile_id 词法。非程序使用者只编辑 md/TOML；config.example.json 只是路径示范，不是授权或本流程前置配置。

| 步 | 操作（计划命令） | 输入 → 输出 / 失败行为 |
|---|---|---|
| 1 | `python -m app policy init --dest prompts/local/my-profile` | 发布示例 → 四文件包、固定双指南与摘要；仅允许 local 直接 profile 子目录（history 保留），存在报 policy_exists，不覆盖；失败不留可加载半包 |
| 2 | 编辑 tone.md | 只改通用语气，如简洁/礼貌/表情，不填个人值；validate 定位文件/行 |
| 3 | 编辑 phrase-bank.md | 按 §3.3 标题/列表改短句，可留空，不复制评测输入或答案 |
| 4 | 编辑 never-say.md | 追加通用禁用表达，可留空，不填真实业务片段 |
| 5 | 编辑 pack.toml | 分档可用 §3.2 完整片段；披露只改 text 且保留 AI助手；字数/频率按 §3.1；allow_keys=[] 可运行，不填事实值 |
| 6 | `python -m app policy validate --pack prompts/local/my-profile` | 四文件+base → ok、有效限制、base/pack 摘要，或定位错误；无设备/模型调用，不改包 |
| 7 | `python -m app policy preview --pack prompts/local/my-profile --case policy-greeting` | base+包+发布的合成输入 → 来源、内容、摘要；未知 ID/坏包失败，不读黄金答案、不连设备、不调模型 |
| 8 | `python -m app policy eval --pack prompts/local/my-profile --suite public --provider <provider-id>` | 公开合成输入+当前包 → 本机报告路径、摘要、逐例判定；必须指定 provider，拒绝 echo/参考回放；调用前显示会外发的私有通用策略及计费范围，须本轮确认 |
| 9 | `python -m app run --pack prompts/local/my-profile --mode read_only` | 包+独立 profile 库 → 只读观测；启动前说明动作、预计占用和独占并获本轮设备确认；只读当前可见状态，不导航/点击、不消耗未读、不写业务终态，可写本机审计 |
| 10 | 停旧进程后同包改 `--mode draft_only`，后续才申请 `--mode auto_send_tier_a` | 前者只保存本机草稿，导航读取仍需具体设备确认；后者另需本轮文本发送授权、A 档开关、当前摘要验收和护栏；改 mode 不授予权限 |

第 6–8 步失败停在本步骤修正，不自动调用下一步。策略子命令成功退出 0，输入/校验/IO/评测不通过退出 2；stdout 单个 UTF-8 JSON，stderr 不回显输入或原异常。成功外层为 {schema_version:1,status:"ok",reason_code:null,result:<命令结果>}；失败为 {schema_version:1,status:"failed",reason_code:<原因码>,errors:[...]}。errors 每项固定 {file,field,line,code}：file 仅项目内相对文件或 null，field 为 schema 键/数组项或 null，line 为 1 起整数或 null，code 不含原值；未知键只定位父表，不能回显可疑键名。

策略原因码固定 invalid_input/invalid_policy/policy_exists/policy_io_error/policy_changed/unknown_case/invalid_provider/eval_failed/authorization_required；字段诊断码固定 missing/unknown_key/duplicate/type/range/vocabulary/coverage/safety_floor/encoding/path/size/sensitive/conflict/format。例如 pack.toml 的 tiers.A[0]、行号与 safety_floor 足以定位越权，无需堆栈；不能定位时置 null。坏包拒绝加载并退出，不自动启动未经确认的只读设备会话。

### 5.1 快照、重评与回滚

第一次通过第 6–8 步后、每次再次编辑**之前**运行：

```text
python -m app policy snapshot --pack prompts/local/my-profile
python -m app policy list
```

snapshot 将校验通过的四载荷文件及固定双指南复制至 prompts/local/history/<snapshot-id>/，ID 为 UTC 时间加随机后缀，存在不覆盖；校验复制前后摘要相同，返回相对路径及 base/pack 摘要，失败不返回成功快照。来源清单另存相邻的 <snapshot-id>.local.json，不放入包，固定字段为 schema_version（整数 1）、profile_id/source_pack（字符串 ID/原活动包相对路径）、base_version/base_hash/pack_hash（版本/摘要字符串）、created_at（毫秒 UTC）；清单不接受额外键。清单与副本均完成才发布成功，缺失或摘要不符的快照不能 restore。list 只列 local 直接活动目录与 history 快照的相对路径、profile_id、摘要、有效性，不输出正文、不自动选最新，链接标为无效。history 不能作为活动包。

回滚先停进程，按租约与 unknown 对账规则确认无在途动作，再执行：

```text
python -m app policy restore --snapshot prompts/local/history/<snapshot-id> --dest prompts/local/my-profile-rollback
python -m app policy validate --pack prompts/local/my-profile-rollback
python -m app policy preview --pack prompts/local/my-profile-rollback --case policy-greeting
python -m app policy eval --pack prompts/local/my-profile-rollback --suite public --provider <provider-id>
python -m app run --pack prompts/local/my-profile-rollback --mode read_only
```

restore 校验清单/副本摘要与 profile_id，base_hash 不同则拒绝自动恢复，用户须先恢复匹配发布或按新 base 修包。运行仍活动、停止未知或未决租约时 policy_changed 拒绝。恢复只复制到不存在的 local 直接子目录，目标存在报 policy_exists；不覆盖原包，保留错误版本便于对比。工具先写不被活动包发现器接受的暂存目录，完整校验后同卷改名发布；中断前的暂存包不得加载，失败报 policy_io_error，原包与快照均保留。用户修正 IO 后选新的空目标重试即可，无需手工拼接半包。

restore 保留原 profile_id，是同一使用者的另一策略版本，目录名可以不同；init 才依据目录名生成新身份。启动新版本 --pack 后仍绑定原 profile 的库与额度，不创建新使用者、不重置计数。同 profile 的版本目录不能同时运行，也不自动改 config.json；以后继续用新 --pack 路径或显式更新本机路径引用。

恢复后重评，不复用旧授权，不回滚数据库、动作证据或已发送内容；base 版本也变了须恢复匹配发布或按新 base 修包。语气/短句/禁用表达/分档/额度/披露/profile/base/模型配置变化均重新 validate → preview → public eval。通过凭证在 data/evals，绑定 base_hash/pack_hash/provider_id/model_id/model_config_hash；run 显示当前摘要，草稿/A 档必须匹配当前验收，否则拒绝提升。read_only 可在独立设备确认后使用。公开 100% 与快照都不构成发送授权。

## 6 黄金集分层

| 层 | 位置 | 用途与外发边界 |
|---|---|---|
| 公开契约集 | 现有 evals/cases.json | 只验证有限契约；模型只见单例输入，不见答案、metadata 或断言 |
| 私有故障回归 | evals/private/regression/（计划） | 脱敏后独立标注的已知故障；可用于修策略，用过后不再称留出 |
| 私有留出 | evals/private/holdout/（计划） | 冻结且未参与调优的观察；只用获准本机模型，不外发；无本机 provider 则未测 |

公开集通过不证明全部语义与真实能力；smoke 只证明回放链路。现有 24 例与未来 Decision 不同，M4 须交付独立映射/断言测试；policy eval 必须实际加载所选包，不能直接调用原 npm 命令就声称评测了包。

公开/私有评测输入、答案和判据不得进入 few-shot 或 phrase-bank；preview 使用单独合成输入，不读 cases/参考输出。runner 每次只交付单例输入，期望留在断言侧。真实故障先脱敏并由人独立定标，不以模型输出充当答案。留出一旦用于修策略就转回归，补独立留出；报告分开记录集合版本/摘要、访问轮次，轮换和维护者见 §12。私有样本脱敏与忽略均不自动授予公开或外发权限。

## 7 运行时加载与供应链

- 只从项目内 prompts/local/<profile> 加载一个活动包；不直接运行 examples/history。显式 --pack 优先于显式 --config 的 policy_pack；都缺失则拒绝，不默认选个人包。当前示例仅 policy_pack，M4 才扩展该加载契约，不与 M0 最小配置混用。
- 路径解析后必须仍在 local 活动目录内；拒绝绝对路径、越界 ..、路径链及包内符号链接/junction。包不下载、不执行；一次读取完整四文件，运行使用已校验不可变内存快照。
- 启动前缺失/校验失败即退出，不连接设备。运行中每次新决策及不可逆动作前重核 base/包摘要，变化记 policy_changed，停止新动作并进入只读暂停；在途动作仍收敛证据，unknown 不重发。不加载坏包的“降级版”。
- 不热加载。修改后停进程、验证、预览、重评并重新取得本轮运行授权；base/包/模型配置变动令旧验收与旧草稿失效，须重新生成，不改历史动作证据。

## 8 多使用者与多 profile

- 同时仅一个活动 profile；同一人的策略版本保持同 ID，换人须 init 新 ID，不只改旧 ID 复用库。
- M1–M2 保持 data/runtime/runtime.sqlite3 合成 v1 库；M4 引入 profile 时，真实运行按 data/runtime/profiles/<profile_id>/runtime.sqlite3 独立库，库元数据绑定 ID，冲突拒绝，旧库不自动导入。一个 profile 的多 app 仍共库。
- 换 profile 必须停旧进程、核对全局设备占用与未决动作；不同库不能各自持有一份手机租约。M4 接真实 run 前须交付独立于 profile 库的进程全局设备门禁，沿用设计说明 §6 的确认停止/隔离规则，不能仅靠 TTL 放行。
- 事实、记忆、额度、草稿、授权、审计不跨 profile 复制。新包无需事实即可离线评测；个人事实需另行设计的确认入口，绝不让用户把值填进策略包。
- 不共享 local；拟公开示例需另行合成和人工审阅，不发布原包快照或真实业务内容。

## 9 公开仓库卫生

- .gitignore 保留 /prompts/local/、/evals/private/、*.local.toml、*.local.json，覆盖历史与私有子目录；data/screenshots 除指南均忽略。忽略不清除已跟踪文件或历史。
- config.example.json 只含 policy_pack，引用 prompts/local/default；不代表包存在，M4 用户需 init 或显式指定自己的包。
- 提交/外发前核对实际文件与请求：不得包含联系人、公司-聊天关联、简历、联系方式、设备序列号、凭据、用户名、绝对路径或私有地址。发现可疑信息按根指南告知位置/类别，不回显原值；不主动读根 config.json 或旧私有数据。
- 提交身份采用使用者认可的公开身份；历史清理由使用者决定，不擅自重写。
- 不发布绕过平台风控、模拟真人或隐藏自动化的内容，保留 AI 助手披露；平台条款与当地法律由使用者自行确认，本文未作法律结论。

1. M4 发布后，未参与设计者只读流程与示例，能改语气、分档、披露，完成 validate/preview/真实 provider eval/快照/恢复，无需改代码或问 schema；当前工具未交付，不声称已达到。
