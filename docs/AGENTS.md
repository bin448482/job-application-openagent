# docs 目录指南

## 一、目录用途

存放本项目的公开文档，主题是“BOSS直聘手机客户端操作与求职自动化”：一份按 ID 组织的静态分析终稿、一份对照当前客户端的实机验证偏差清单、一份简化架构设计说明、一份实施计划、一份多应用扩展与分层说明、一份公开仓库与策略包说明、一份新环境自动化部署方案、一份场景测试方案及其三轮自审记录、一份 M3 读取阶梯与最小数据契约、一份 M4c 运行绑定与事实/设备门禁设计事实、一份 M5 动作护栏与对账设计事实、一份 M0–M5 操作手册，供后续实现真实运行绑定、运行时记忆、设备执行器与部署入口时对照。

终稿中的结论全部来自对旧项目 `scripts/` 的**静态阅读**，未运行代码、未连接设备；实机验证文档的记录来自一台真机的 UI 层级读取与经使用者逐轮确认的受控操作。两者都不构成对真实手机的执行授权，也不代表当前仓库已有对应实现。

## 三、与其他目录的关系

- 根 `AGENTS.md` 保存全局工作规则、项目事实与根索引；本文件只做本目录索引，不复述全局规则。
- `docs/` 与源码目录没有运行时依赖：终稿引用旧项目的 `scripts/`、`scripts/core/`、`scripts/jobs/`、`scripts/hr/`、`scripts/heartbeat/` 作为证据来源，但当前仓库没有这些代码。
- 与 `evals/` 无关：评测只使用合成案例，不读取本目录，也不把终稿中的旧项目路径当作可执行输入。
- 终稿第 3 节引用的 `docs/求职展示资源.md` 属于旧项目文件，当前仓库不存在，不应据此创建或读取。

## 四、维护要求

1. 新增、改名、移动或删除本目录文件时，必须同步更新本文件的“当前文件清单”和根 `AGENTS.md` 的根目录索引；两处描述必须一致。
2. 技术结论必须带 `file:line` 证据（源码文件 + 行号或行号区间）；无法给出证据的推断必须写入终稿第 8 节“未覆盖与不确定项”，不得混入正文当作事实。
3. 不写入真实个人信息与敏感值：真实姓名、联系方式、简历内容、公司-聊天关联、设备序列号、密钥、令牌、Cookie、带凭据的 URL 一律不得出现；路径只用相对路径，设备标识只用 `<serial>` 等占位符。发现疑似敏感信息时按根指南的“开源项目敏感信息告知”处理，不在对话或差异摘要中复述原值。
4. 编号规则：一个 ID = 一次可观察动作或一次判定；ID 形如 `域前缀-字母两位数字`（`CORE-`、`JOBS-`、`HRR-`、`HRA-`）。新增 ID 必须在终稿第 1–5 节给出唯一定义，并在第 9 节索引中登记。
5. 设备原语唯一权威：读屏、点击、滑动、返回键、截图只能由 `CORE-` 定义；其它章节只写“调用 `CORE-Axx`”并保留业务定位与判据，不得复制第二份原语定义。
6. 合并或改写章节时，保留原有技术判断、行号与失败码；只允许去重、改编号、补交叉引用。删除或改写结论必须同时更新第 8 节的不确定项。
7. 提交前自查：所有 ID 定义唯一、正文引用无悬空、0–9 小节齐全、无绝对路径与本机用户名；并确认未把旧项目运行数据、凭据或个人事实带入文档。
