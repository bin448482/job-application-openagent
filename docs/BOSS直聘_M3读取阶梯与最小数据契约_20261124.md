# BOSS直聘 M3 读取阶梯与最小数据契约（离线开发约定）

> 文件用途：定稿 M3 读取阶梯、页面/职位/聊天/未读读取值类型、跨屏消息与入站身份、像素标定、输入夹具、失败边界和决策门禁的离线最小契约。本文是当前 M3 离线实现约定，不是真机标定记录，不构成设备执行授权，也不表示 M3 真机只读一轮已通过。

## 0 范围与依据

- 依据：实施计划 M3；简化架构说明 §5.3–5.4、§6；原子化文档 `CORE-W14`、`CORE-M01`/`CORE-M04`、`JOBS-P01`/`JOBS-P05`–`P07`、`HRR-R14`/`R15`/`R17`/`R19`–`R22`；实机验证偏差 V1–V7；多应用扩展说明 §5 的端口边界。
- 本轮只实现纯合成 XML、纯合成 RGBA 像素、模拟 ADB 子进程和本机证据保存；不连接真实设备、不调用外部模型/网络、不读取根 `config.json`、旧库或个人事实。
- M3 不调用业务库、不 `claim/start/finish`、不写 `hr_messages`、不关闭发现、不推进 `verified_at` 或已读基线。真实 `read` 在共享 OS 设备门禁交付（M4）前必须在任何 ADB 子进程启动前拒绝，profile 内的 `primary` 任务锁不能替代该门禁。

## 1 唯一外层与值类型分派

继续使用 `app/domain/models.py` 的 `ReadResult` 固定七键：`status/value/reason_code/snapshot_id/observed_at/source/confidence`。

- `status` 仅 `ok/failed/undetermined`；`source` 仅 `hierarchy/pixel/vision/human/fixture`；`confidence` 仅 `low/medium/high`。
- `ok` 必须 `value` 非 null 且 `reason_code=null`；`failed/undetermined` 必须 `value=null` 且原因属于既有固定词表。
- `failed` 原因仅 `device_disconnected/device_unauthorized/device_offline/wrong_page/invalid_xml/invalid_fixture`；`undetermined` 原因仅 `unread_unverified/identity_ambiguous/incomplete_snapshot/stale_snapshot/uncalibrated_profile`。不新增 M3 顶层原因。
- `value` 按实际类型严格分派：`UnreadSnapshot`（M2 既有）、`PageSnapshot`、`JobList`、`JobDetail`、`UnreadRead`、`Conversation`；未知类型一律拒绝。`upsert_snapshot` 和 `persist_and_aggregate` 额外显式只接受 `UnreadSnapshot`，不把 M3 值送入 M1 仓储。
- 所有值类型全部键必填、拒绝额外键；枚举严格、bool 不冒充整数、摘要/UUID/UTC 复用现有校验算法。

## 2 字段证据与决策门禁

`FieldEvidence` 固定键：

| 键 | 类型/取值 | 约束 |
|---|---|---|
| `field` | `page/job_cards/job_detail/unread_badges/conversation_identity/conversation_inbound` | 必填，固定枚举 |
| `source` | `hierarchy/pixel/human` | `unread_badges` 可为层级或像素；其余字段仅层级；人工确认仅来自显式人工输入，不由程序伪造 |
| `confidence` | `low/medium/high` | 层级结构 `high`、像素 `medium`、人工 `high`；未知/失败可为 `low` |
| `state` | `ok/unknown/failed` | `ok` 时 `reason_code=null`；`unknown/failed` 时原因非空 |
| `reason_code` | null 或固定词表 | unknown：`missing_signal/ambiguous_signal/uncalibrated_region/calibration_mismatch/unverified_identity/incomplete_coverage/stable_identity_unverified/unverified_semantics`；failed：`invalid_xml/wrong_page/invalid_fixture` |

`ReadResult.status=ok` 只表示结构和解析确定，不等于可决策。读取用例提供 `is_actionable(result) -> (bool, gate_reason)` 门禁；`actionable=false` 时不得调用模型或动作。门禁原因固定为 `not_ok/field_unknown/identity_ambiguous/incomplete/no_target`。`undetermined` 永远不可决策。合成输入得到 `actionable=true` 或 `inbound_state=known` 只表示离线契约自洽，不提供真实发送授权。

### 2.1 阶梯内部类型

`FieldReading`（单级原始结论）固定键：`field/app/profile_id/profile_version/snapshot_id/observed_at/layout_context/source/confidence/state/count/reason_code`。

- `field` 固定 `unread_badges`（当前唯一需要像素后备的字段）；`app` 固定 `boss`；`profile_id/profile_version/layout_context` 为非空字符串（layout_context 为 64 位摘要）；`snapshot_id` 为规范 UUID；`observed_at` 为毫秒 UTC；`source` 仅 `hierarchy/pixel/vision/human`；`confidence` 仅 `low/medium/high`；`state` 仅 `present/absent/unknown/failed`；`count` 为非负整数或 null；`reason_code` 为 null 或固定字段原因。
- present 可用层级精确计数；像素 present 的 `count=null`；absent 必须 `count=0`；unknown/failed 的 `count=null` 且原因非空。失败原因取 `invalid_xml/wrong_page/invalid_fixture`，未知原因取 §2 词表。

`FieldResolution`（合并后结论）固定键：`field/app/profile_id/profile_version/snapshot_id/observed_at/layout_context/state/count/reason_code/source/confidence/requires_human/evidence`。

- `state` 仅 `present/absent/undetermined/failed`；`source` 为 null 或 `hierarchy/pixel/vision/human`；`confidence` 为 null 或 `low/medium/high`；`evidence` 是实际参与比较的 `FieldReading` 数组，保持层级→像素→视觉→人工顺序。
- `failed` 必须保留前级失败原因；后续未知或成功不得改写为 undetermined/ok，CLI 输出与过程日志分别可观察该失败原因。
- 所有参与同一字段比较的 reading 必须共享 `app/profile_id/profile_version/snapshot_id/observed_at/layout_context`；上下文不同时返回 `undetermined/ambiguous_signal` 并要求人工，不得拼成 ok。

## 3 页面读取 `PageSnapshot`

固定键：`app/profile_id/page/signals/field_evidence`。

| 键 | 约束 |
|---|---|
| `app` | 固定 `boss` |
| `profile_id` | 非空字符串 |
| `page` | `main/chat_list/chat_detail/job_detail/popup/login/recommend_feed/unknown` |
| `signals` | 去重、按固定顺序的字符串数组，元素仅 `popup/login/chat_detail/job_detail/chat_list/recommend_feed/bottom_tabs`；未知页可为空 |
| `field_evidence` | 恰好一项，`field=page`、`source=hierarchy`；`page=unknown` 时 `state=unknown` 且原因非空，否则 `state=ok` |

页面分类优先级沿用 `CORE-W14`：弹窗 → 登录 → 聊天详情 → 职位详情 → 推荐流 → 聊天列表 → 主界面底部标签 ≥2 → unknown。页面未知仍可返回 `status=ok`（结构可读），但 `is_actionable` 为 false；不能把未知页面当作主界面或列表。

## 4 职位读取

### 4.1 `JobCard`

固定键：`job_key/identity_hash/title_raw/title/company_raw/company/salary_raw/salary`。

- `title_raw/company_raw/salary_raw` 为行内唯一节点原样非空文本。
- `title = title_raw.strip(" @%&")`（仅首尾，按 `JOBS-P01`）；`company = company_raw.strip()`；`salary = salary_raw.strip()`。比较值只用于同一应用内身份和展示比较，不改写原文。
- `identity_hash = H([title, company, salary])`；`job_key = "boss:job:" + identity_hash`。校验时从原值重新规范化并重算，不信任输入键或摘要。
- `JobList` 内同一 `identity_hash` 重复时保留摘要但所有重复项 `job_key=null`，不按屏幕序号或坐标生成稳定职位身份。
- 公司/职位身份不沿用旧项目别名、私人策略或旧库。

`JobList` 固定键：`app/profile_id/coverage/cards/field_evidence`。`coverage` 固定 `viewport`；`cards` 非空；`field_evidence` 恰好一项 `field=job_cards`。零张完整卡片不是“没有职位”，而是 `undetermined/incomplete_snapshot`，不写空列表冒充成功。

### 4.2 `JobDetail`

固定键：`app/profile_id/job_key/identity_hash/title_raw/title/company_raw/company/salary_raw/salary/recruiter_raw/recruiter/location_raw/location/description/description_hash/description_length/complete/missing_fields/field_evidence`。

- 必需节点：非空 `tv_description` 等价正文，且存在 `btn_chat`/`btn_continue_chat` 等价沟通按钮；缺失为 `failed/wrong_page`。
- `description` 为原样正文（仅内存与合成 CLI 数据区，不写日志/事件/库）；`description_hash=H(description)`；`description_length=len(description)`（Unicode 字符数）。
- `complete` 必须为 true 才可返回 `ok`。正文含“查看更多”或以 `…`/`...` 结尾为 `undetermined/incomplete_snapshot`，`value=null`，不得把截断正文交模型补全。
- `recruiter`/`location` 可为 null；对应缺失名称写入 `missing_fields`（去重、固定顺序 `recruiter/location`），不猜值。
- `job_key` 与 `JobCard` 同算法、同身份域；详情页与列表标题/公司/薪资比较值必须重算一致。

## 5 未读行读取 `UnreadRead`

固定键：`app/profile_id/coverage/rows/unread_state/field_evidence`。

- `coverage` 仅 `viewport/all`；仅 `full_traversal` 首尾证明均真时可为 `all`，否则 `viewport`。
- `rows` 非空；空列表不是“无未读”，返回 `undetermined/incomplete_snapshot`。
- `unread_state`：任一行 `present` 即 `present`；仅 `coverage=all` 且所有行 `absent` 才 `absent`；其余 `unknown`。
- `field_evidence` 恰好一项 `field=unread_badges`；任一行未知时 `state=unknown`，原因按 `ambiguous_signal/uncalibrated_region/calibration_mismatch/missing_signal/incomplete_coverage` 优先级。

`UnreadRowRead` 固定键：`identity_hash/conversation_key/state/count/source/confidence/reason_code`。

- 身份仍按 `H([联系人,公司,职位])`，与 `boss:conv:` 既有算法一致；重复或缺失身份保留摘要但 `conversation_key=null`，不按行号生成会话键。
- `state` 仅 `present/absent/unknown`；`present` 可带层级精确计数，像素只能证明存在故 `count=null`；`absent` 的 `count=0`；`unknown` 的 `count=null` 且原因非空。
- `source` 仅 `hierarchy/pixel/human/none`；`none` 只用于跨级冲突后的未决行。`confidence` 同字段证据。

## 6 聊天读取 `Conversation` 与消息身份

固定键：`app/profile_id/conversation_key/identity_hash/contact/contact_verified/role/message_identity_verified/read_complete/messages/inbound_state/latest_inbound_key/field_evidence`。

### 6.1 会话身份核对

- 输入上下文 `conversation_context` 固定 `{contact, company, position, source_snapshot_id}`。当前 M3 离线夹具中的该对象只是显式合成发现/采集链上下文，不是实际仓储来源认证；格式正确和联系人相等不能证明 company/position 真来自已保存发现。
- 实际聊天页 `contact` 必须与上下文 `contact` 逐字相等；否则 `undetermined/identity_ambiguous`，不生成值。
- `identity_hash = H([实际 contact, 上下文 company, 上下文 position])`；`conversation_key="boss:conv:"+identity_hash`。校验重算，不信任 context 或 manifest 提供的键；这仅证明与输入上下文自洽，不是会话身份实证。
- 生产后续接线必须核验 context 来自本轮已保存发现且处于同一次导航/采集链，或重新观测到充分身份；无可信来源/链时保持 `identity_ambiguous`。不能称已实际核验同名不同岗位，也不虚构公司/职位或继承旧别名。
- `contact_verified=true`、`conversation_key`/`identity_hash` 非空是 `ok` 的必要条件。`source_snapshot_id` 只作本机合成/后续来源核对，不写入输出，也不作为已认证来源的证明。

### 6.2 `ChatMessage`

固定键：`kind/direction/text/content_hash/time_hint/stable_identity_hash/stable_identity_source/repeat_safe/truncated/direction_evidence/message_key`。

| 键 | 约束 |
|---|---|
| `kind` | `text/media/resume_card/card/system_tip/time/unknown` |
| `direction` | `incoming/outgoing/system/unknown` |
| `text` | 文本/系统行原样正文或 null；只进内存与合成 CLI 数据区，不写日志/事件/库 |
| `content_hash` | 文本行为 `H(text)`；系统行为 `H(text)`；其它为 null。只用于内容比较，不生成消息身份 |
| `time_hint` | 原样时间文本或 null |
| `stable_identity_hash` | null，或 `H(["boss","message","stable-id",raw_stable_id])`；raw 值取 profile 指定节点的 `content-desc` 原值，不规范化 |
| `stable_identity_source` | null 或固定 `app_message_id`；与摘要同空或同非空 |
| `repeat_safe` | 必须等于 `stable_identity_hash is not null`；内容指纹、同秒、坐标、resource-id 布局、屏幕序号、当次 UUID 都不能置 true |
| `truncated` | 文本截断标记；true 时不可生成可发送入站身份 |
| `direction_evidence` | 去重字符串数组，元素仅 `avatar/bubble/sent_status`；系统行为空 |
| `message_key` | null，或 `"boss:msg:"+H([conversation_key, stable_identity_hash])`；仅 `repeat_safe` 且会话身份已核对时非空 |

方向规则：系统行 `direction=system`；其它行至少一路证据（头像左右、气泡左右、我方发送状态）且所有可用证据一致才得 `incoming/outgoing`；缺失或冲突为 `unknown`。头像/气泡只有相对行矩形左右中心，不使用屏幕序号。

消息身份收紧：

- 只有 profile 显式声明并验证过 `conversation_stable_id_verified=true` 的应用消息标识，才可给出 `stable_identity_hash`。合成 profile 可用该语义验收正路径；未标定的真实版本必须 `conversation_stable_id_verified=false`，消息 `repeat_safe=false`、`message_key=null`。
- `content_hash/time_hint/repeat_safe` 的关系固定为：内容指纹可比较内容，但同正文同秒、卡片摘要同秒、系统 token 同秒都可能碰撞，不构成稳定身份；不得用 `content_hash` 生成 `message_key` 或裁剪跨屏重叠。
- 合并后同一 `stable_identity_hash` 在非边界裁剪位置重复，全部重复项丢失 `stable_identity_hash/repeat_safe/message_key`，会话 `inbound_state=unknown`，不猜哪一条是同一消息。
- 稳定 ID 必须在 parser 内从实际节点的原值推导；同一稳定 ID 若对应不同 `content_hash`、不同方向或不同会话，保持歧义并清空可发送键。原始 ID 不写日志、不进入公开摘要。
- 跨屏只裁剪相邻页边界上 `stable_identity_hash` 非空且 `kind/direction/content_hash/time_hint` 完全一致的连续最长重叠。完全相同的画面且无稳定身份时不得自动去重，宁可重复不丢。

### 6.3 `inbound_state` 与可发送入站身份

- `known`：`read_complete=true`、会话身份已核对、`message_identity_verified=true`、消息非空、不存在 `kind=unknown` 或 `direction=unknown` 行、最新非系统消息为 `incoming` 文本、正文非 null、`truncated=false`、`repeat_safe=true`、`message_key` 非空，且其后的行只允许 `system_tip/time`。此时 `latest_inbound_key` 必须等于该消息键。
- `none`：`read_complete=true`、会话身份已核对、消息为空或最新非系统消息为 `outgoing`/全部为系统时间行，且无未知行；`latest_inbound_key=null`。
- `non_text`：`read_complete=true`、会话身份已核对、最新非系统消息为 `incoming` 且 kind 为 `media/resume_card/card`，且无未知行；`latest_inbound_key=null`。
- `unknown`：其余情况（未读全、身份未核对、身份重复、截断、未知行、最新方向未知等）；`latest_inbound_key=null`。
- `read_complete`：单页消息列表显式 `scrollable="false"` 时可 true；多页必须 `coverage_proof.kind=full_traversal`、首尾证明均真、所有页 `status=ok`。未读全的最终结果返回 `undetermined/incomplete_snapshot`、`value=null`，不以部分消息生成入站身份。
- 角标消失、发现已打开过或单张截图都不证明无新入站；本层没有库，关闭发现留给上层调度，且必须另有消息身份证据。

## 7 读取阶梯 `field_evidence` 与像素

### 7.1 阶梯顺序

1. 层级 XML：默认主路径，字段 `source=hierarchy`、`confidence=high`。
2. 像素/几何：仅当同一字段层级为 `unknown`，且存在显式合成标定；`source=pixel`、`confidence=medium`。
3. 视觉：默认关闭；即使启用，也不能仅凭视觉高置信放行。无独立结构/像素交叉证据时转人工；本 Task 不调用视觉模型。
4. 人工：只能来自显式人工输入，输出 `source=human`、`confidence=high`；程序不得伪造人工确认。

合并规则：

- 任一前级 `failed` 直接结束该字段并向上保留明确失败，不调用后续级别掩盖。
- 前级 `present/absent` 已确认时，后级同值只作证据，不得覆盖；后级不同值构成跨级冲突，字段 `undetermined`、`requires_human=true`。
- 层级未知、像素未知且视觉关闭/无交叉证据 → 人工出口。
- 字段未决时，完整结构可返回 `status=ok` 并在 `field_evidence` 标 `unknown`，但门禁必须拒绝决策；结构性失败/未决仍 `value=null`。

### 7.2 像素标定与纯解析

标定固定键：`calibration_id/app/profile_id/version/calibrated/absent_state_verified/resolution/badge_region/target_color/tolerance/threshold_pixels/source/calibrated_on`。

- `app` 仅 `boss`，`profile_id/version` 必须与读取 profile 相同；`calibrated`、`absent_state_verified` 为 bool；`resolution=[width,height]` 正整数；`badge_region` 为相对行矩形的 `[left,top,right,bottom]` 比例（0–1、正面积）；`target_color=[r,g,b]` 0–255 整数；`tolerance` 0–255 整数；`threshold_pixels` 正整数；`calibrated_on` 为 `YYYY-MM-DD`。
- 合成标定 `source` 必须如实标为 `synthetic`；自称 `calibrated=true` 不代表真实设备已验证。真实阈值、区域、字体与分辨率均未测。
- 合成原始截图固定为 16 字节小端头：`uint32 width`、`uint32 height`、`uint32 format`、`uint32 colorspace`；当前只支持 `format=1`（RGBA）且 `width/height` 为正整数、`width*height` 不溢出 Python 整数、随后恰有 `width*height*4` 字节；不支持域为失败，不暗示该格式覆盖所有真实 ADB 版本。
- 分辨率不等于标定、profile_id/version 不一致、区域越界或行几何不可读时不得变 `absent`。
- 强像素判定：目标色三分量各自差值 ≤ tolerance 计为强像素；数量 ≥ `threshold_pixels` 为 `present`。只有标定明确 `absent_state_verified=true` 且分辨率/区域/几何全部匹配时，低于阈值才可 `absent`；否则为 `unknown/uncalibrated_region`。像素只能证明存在，不生成精确计数。
- 区域浮点必须有限且 0–1、正面积；巨大整数/坐标换算溢出按 M2 已修边界回到 `uncalibrated_region`，不得抛未分类异常或静默成 absent。
- 损坏头/长度/格式/越界区域为字段 `failed`，合成入口映射 `failed/invalid_fixture`；分辨率/profile/version 不一致为 `unknown/calibration_mismatch`；`calibrated=false`、`absent_state_verified=false` 或区域缺失为 `unknown/uncalibrated_region`。

### 7.3 读取 profile 与版式上下文

读取 profile 固定键：`profile_id/app/version/calibrated/selectors`，全部必填、拒绝额外键。`selectors` 固定键及类型：

| 键 | 类型/约束 |
|---|---|
| `bottom_labels` | 非空去重字符串数组，至少 2 项 |
| `popup_markers`/`login_markers`/`recommend_markers` | 去重字符串数组，可为空；仅精确文本匹配 |
| `chat_list_suffix` | 非空字符串 |
| `chat_detail_suffixes` | 非空去重字符串数组 |
| `job_description_suffix` | 非空字符串 |
| `job_chat_suffixes` | 非空去重字符串数组 |
| `job_title_suffix`/`job_salary_suffix`/`job_company_suffix`/`job_recruiter_suffix`/`job_location_suffix` | 非空字符串 |
| `conversation_list_suffix`/`conversation_title_suffix`/`conversation_subtitle_suffix`/`conversation_row_suffix`/`conversation_text_suffix`/`conversation_time_suffix`/`conversation_system_suffix`/`conversation_card_suffix`/`conversation_avatar_suffix`/`conversation_bubble_suffix`/`conversation_status_suffix` | 非空字符串 |
| `conversation_stable_id_suffix` | 非空字符串或 null |
| `conversation_stable_id_verified` | bool；为 true 时 suffix 必须非空并已有显式稳定语义证据，为 false 时不得产出稳定消息键 |
| `unread_list_suffix`/`unread_row_suffix`/`unread_name_suffix`/`unread_company_suffix`/`unread_position_suffix`/`unread_badge_class` | 非空字符串 |
| `unread_badge_region` | null 或相对行的 0–1 比例四元数组，正面积 |

profile 只描述当前合成版式；`calibrated=true` 仅表示该合成 fixture 可解析，不是真实版本标定。真实版本必须另取标定证据，不能复制合成值。

同一字段的层级/像素/人工 reading 必须共享同一 `app/profile_id/profile_version/snapshot_id/observed_at`，并由 profile_id/version 与布局选择器共同构成版式上下文；上下文不一致时字段不可合并为 ok。`UnreadRowRead` 的 `source/confidence/state/count/reason_code` 联动及 `field_evidence` 必须由校验器从行结果重算核对，不能各自合法但互相矛盾。

## 8 输入夹具与 CLI

新增 `read --fixture <项目内相对文件>`，不提供 `--db`、不提供真实设备入口。manifest 固定键：

```json
{
  "profile_path": "profile.json",
  "app_version": "<profile.version>",
  "observed_at": "2026-11-24T00:00:00.000Z",
  "kind": "page|job_list|job_detail|unread|conversation",
  "hierarchy_paths": ["page.xml"],
  "coverage_proof": {"kind": "viewport", "top_proven": false, "bottom_proven": false},
  "conversation_context": null,
  "pixel": null
}
```

- `conversation_context` 仅 `kind=conversation` 必需，形状见 §6.1；其它 kind 必须 null。
- `pixel` 仅 `kind=unread` 可为 `{calibration_path,raw_path}`，其它 kind 必须 null。
- `page/job_list/job_detail/unread` 恰好一页；`conversation` 一页或多页。所有引用相对 manifest 目录且必须在该夹具目录内，拒绝绝对路径、`..`、链接/junction、缺失或越界。
- 所有键必填、拒绝额外键；共享严格 JSON 入口拒绝重复对象键；`app_version` 不等于 profile.version 或 `calibrated=false` 为 `undetermined/uncalibrated_profile`。
- 与 M2 兼容方式：M2 `sense` manifest/profile 保持原合同，不被 `read` 读取；M3 `read` 使用独立 profile/manifest，不把合成 profile 当作真实标定，也不把 M2 fixture 自动升级。
- CLI 输出固定外层 `{"schema_version":1,"result":<ReadResult>,"actionable":<bool>,"gate_reason":<null|固定原因>}`；`status=ok` 且 `actionable=true` 退出 0，其它退出 2。失败/未决 `value=null`；字段未知但结构完整可输出 `ok`，但 `actionable=false`。
- `read --device` 或任何真实入口在共享设备门禁交付前于子进程启动前拒绝为 `invalid_input`；本 Task 不调用真实 ADB。

## 9 采集适配器与证据

- `AdbScreenReader` 只用参数数组、`shell=False`、每条 5 秒超时、不重试：`adb -s <serial> shell uiautomator dump <设备临时路径>`、`adb -s <serial> shell cat <设备临时路径>`、`adb -s <serial> exec-out screencap`。
- 失败、超时、ADB 缺失、非零退出统一为 `device_disconnected`（适配器安全错误）；进程日志只写固定阶段/命令/结果/耗时/固定错误类别，不写 serial、路径、XML、截图、正文。
- 层级 XML 与原始 RGBA 证据只写调用方指定的项目内被忽略目录，文件名含独立 UUID；适配器返回内存内容与相对/受控证据标识，不把绝对路径写入业务 JSON 或日志。
- 测试只 mock `subprocess.run`，断言参数、超时、不重试、证据保存、零真实 ADB；不读取真实设备或 PID。

## 10 场景责任

| 场景 | 本离线实现的判据 |
|---|---|
| SC-R03/R04 | 一次定向核对接口只接受新采集结果；仍无可定位正目标返回 `unread_unverified`，不按计数或预览变化造目标 |
| SC-R05/R06 | 打开后角标消失不关闭发现；`inbound_state` 需消息身份/方向/完整性共同满足，未读全返回 `incomplete_snapshot` |
| SC-R07 | 跨快照新消息需独立稳定身份；旧快照过期不合并，同正文同秒不作为新消息证明 |
| SC-R08 | 角标延迟/消失不单独证明 `absent` 或无新入站；竞争未知保留人工出口 |
| SC-R09 | 新招呼语义仍不视为未读筛选等价；本层不据此生成入站身份 |
| SC-R10 | 截断、方向未知、身份重复/缺失均 `undetermined` 或无 inbound key，不丢其它已定位正目标 |
| SC-R11 | 返回后必须重新分类页面；旧发现仍按消息证据核对，不按返回次数假定列表 |
| SC-R12 | 版本/版式/控件 0 或多候选 → `uncalibrated_profile`/`identity_ambiguous`；不沿用旧坐标/阈值 |
| SC-R13 | 字段冲突 → `undetermined`/人工；明确 failed 不降级掩盖；视觉默认关闭且无交叉证据不放行 |

### 10.1 定向核对、序列化与门禁稳定性

- `targeted_verification_outcome(initial, targeted, queued_keys, *, now)` 只接受新采集结果：`targeted.snapshot_id` 必须不同于 initial，`observed_at` 距 `now` 在 0–5 秒且不得早于 initial，`app/profile_id` 必须与 initial 相同；同快照重放返回 `unread_unverified`，旧/未来时间返回 `stale_snapshot`，跨 app/profile 返回 `identity_ambiguous`。之后才按 `stop_reason_for` 判定是否解除定向核对。
- M2/M3 的 `ReadResult` 七键与 `UnreadSnapshot` 深层序列化只有 `app/usecases/payload.py` 一处真实实现；`sense` 与 `read` 共用，`sense` 仍显式只接受 `UnreadSnapshot`。固定 JSON 使用显式字段投影，不用 `dataclasses.asdict` 扩大白名单；M2 `SIGNAL_KEYS` 顺序与全部字段保持。
- `read_from_device` 在任何门禁检查或设备调用前拒绝不可调用 parser；共享门禁协议在 M3 只是端口，M4 实现未交付，测试注入的假门禁不代表生产共享门禁已实现。
