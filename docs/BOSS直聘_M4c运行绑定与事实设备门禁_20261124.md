# BOSS直聘 M4c 运行绑定与事实/设备门禁设计事实

> 文件用途：记录 M4c 已实现的 profile 独立事实库、本机事实确认入口、固定 OS 共享 SQLite 设备门禁、restore 真实活动检查、验收凭证复核与 `run check` 预检的设计选择、边界和未测项。本文只描述合成与模拟验收，不构成真实设备、模型、发送或 M5 动作授权。

## 1 范围与结论

M4c 的目标是让 M5 可以在实际生产护栏上实现动作，而不是提前实现动作。已交付：

- `facts` 本机交互 CLI：按 profile 逐字段提案/确认/查看/撤销/遗忘长期事实；确认写使用固定门禁库写事务覆盖同 profile 校验、profile 打开/迁移与事实提交。
- profile 独立运行库：`data/runtime/profiles/<profile_id>/runtime.sqlite3`，复用 M1 v1 五表并追加最小 profile 元数据/事实/事实审计表。
- 固定 OS 位置共享 SQLite 设备门禁：唯一 `primary` 占用、先占后用、全会话持有、异常隔离、不自动解锁。
- 生产 `policy restore` 接真实活动/未决检查；`policy acceptance check` 复核验收摘要；`run check` 做 mode/设备确认/验收/跨库绑定预检。

仍未交付：M5 动作与运行时决策记忆、真实事实对账开锁、M6–M8 调度/清理/灰度、真实 provider、真机与完整 MVP 运行。`run check` 通过不等于发送授权。

## 2 profile 库与事实入口

### 2.1 存储选择

- 事实值只写 profile 独立库，不写策略包、日志、公开报告或错误。旧 `data/runtime/runtime.sqlite3` 不自动导入；不存在 1→2 迁移。
- profile 库完整对象集 = M1 已定 v1 五表/索引 + `profile_meta` + `profile_facts` + `profile_fact_events`。五表 DDL 原文复用，不改变合同；profile 库有自己的完整结构核验和绑定 ID。
- 不同 profile 使用不同固定路径，事实/元数据/未来额度/动作历史不跨 profile 复制；同 profile 的换策略版本仍是同一库、同一身份。

### 2.2 事实语义

- 只注册 `work_location`、`salary_expectation`、`years_experience`。每项事实固定 `key/value/source=user_confirmed/expires_at` 投影；来源 ID、确认时间与状态在本机库保管，不加入模型协议。
- 程序生成来源 ID，不从模型 reply/evidence 或 HR 文本生成确认来源。
- 每次 `set` 未确认只返回提案；确认后从库中重读并再次显示。同键多个 active 来源不凭较新时间择一，统一转 `conflict` 待办；`--replace` 才显式作废旧 active 来源。
- `revoke` 保留来源历史；`forget` 删除事实行并只保留来源 ID/无值审计。明确不宣称擦除 SQLite WAL 或既有本机备份，也不重写 Git 历史。
- 到期、缺失、冲突由可信持久化侧先筛选，再交既有唯一 `select_allowed_facts`；不造第二套事实协议或自然语言解析器。

## 3 共享设备门禁

- 唯一位置：Windows `LOCALAPPDATA/job-application-openagent/device-guard.sqlite3`；不随仓库、worktree、clone、`--pack` 或 `--config` 改变，不提供自选路径。非 Windows 或缺失固定根拒绝真实占用。
- 唯一逻辑设备 `primary`；行内只存 profile_id、原 profile 库规范路径、owner/pid/host/nonce 与 `held/quarantined`，不存事实、聊天或序列号。路径只在本机，不写公开报告。
- 每个真实会话（含 read_only）先 `BEGIN IMMEDIATE` 条件插入；存在任何状态即拒绝。取得后才打开 profile 库/任务/设备；跨库失败保留占用，不补偿为空闲。acquire 使用零等待连接，写锁竞争立即 `device_busy`；verify/release/recover 保留有界等待与完整身份复核。
- 启动、续租与每条设备命令前复核 nonce/profile/路径/held。崩溃、PID 消失、TTL、重启、换 profile 都不自动释放；异常/未知/库不可读保留并隔离。正常释放要求操作已收敛、无 pending/unknown 且子命令明确退出。
- M0 `doctor --device` 与 M3 真实采集适配器接同一门禁；`doctor` 需要本轮 `--confirm-device`，未确认不启动任何 ADB 子进程。M3 仍不暴露真实 `read --device` 入口。

## 4 restore、验收与 run check

- `restore` 使用真实 profile/共享占用检查：held 为 active，quarantined/坏库/绑定不符为 unknown，M1 leased/running 为 active，blocked 为 unknown，只有 stopped 才恢复。失败不换目录解锁、不重置额度。
- `policy acceptance check` 只读比较验收凭证与当前 base/pack（可选 provider/model/model_config_hash）；摘要变化返回 `policy_changed`，旧草稿/旧凭证失效。它只证明模型评测凭证匹配，不授予设备或发送权限。
- `run check` 是预检：read_only 要求本轮设备确认；draft_only 另要求当前验收；`auto_send_tier_a` 在 v1 固定 C 且缺独立前置判据时始终拒绝。预检先占共享库再打开 profile 库，失败保留占用并隔离；不探测设备、不调用模型、不执行动作、不预建 M5 表。
- 决策边界继续复用 M4b 唯一 `decide`：桥前/重试前/桥后重读 base/pack 与租约；唯一仓储快照 `RepositorySnapshot` 只做重读，不复制摘要或校验算法。合法 profile 库经完整 profile 校验后由唯一 `SqliteStore` 复用现有任务能力；`ProfileSessionLease` 每次读取都重核 profile 库任务/设备租约与共享门禁身份，失效/失配/过期返回无租约，由 `decide` 桥前拒绝。

## 5 第 1 轮集中返修（D01–D08）

- D01：门禁 acquire 保存完整 owner_id/pid/host/nonce/profile/路径；verify 与 release 写事务共用同一完整身份复核，任一变化不删除原占用。
- D02：真实 ADB 探针/采集适配器缺失 gate 时在零 subprocess 处固定拒绝；保留测试 fake gate。
- D03：门禁库只允许 user_version=0 且无用户对象的明确新空库初始化；已有库核验版本、完整对象集与 DDL，未知/额外/旧表不改写。
- D04：只有明确不存在才是无状态正例；门禁库/profile 库存在但为目录或不可读时 restore 返回 unknown，实际 CLI 不发布目标包；facts show 同步拒绝。
- D05：门禁适配器唯一记录 acquire/verify/release/quarantine 的 started/终态；run/restore 的 profile 打开记录配对日志；CLI 不再重复记同一门禁操作。
- D06：facts 带 `--pack` 时 pack.profile_id 必须等于 `--profile`，否则 `profile_mismatch`。
- D07：合法 profile 库在完整 profile 校验后由唯一 `SqliteStore` 复用任务能力，普通 M1 库验证不放宽；`current_lease_expiry` 与 `ProfileSessionLease` 每次重核任务/设备租约和共享门禁，领取/续租/失效/decide 桥前后均有合成证据。
- D08：删除重复快照包装，统一 `RepositorySnapshot`；`select_allowed_facts_with_reasons` 成为唯一事实选择规则，profile 侧只投影 active 行并组织无值待办。
- 实际 CLI 受控合成桥 eval→snapshot→restore→validate/preview→eval 串行闭环已运行，三摘要一致且同 profile 事实/任务审计不变。

## 6 第 2 轮集中返修（E01–E04）

- E01：门禁端口新增 `DeviceSessionIdentity`/`session_identity`，一次性返回 held 会话的 profile、原库、owner 与 nonce。`ProfileSessionLease` 保存取得时 `Lease/Owner/nonce`，同时比较 store profile/path、门禁 profile/原库/owner、任务与设备两行 owner/pid/host/nonce 及到期；跨 profile、另一 clone 路径、复制库且参数指向副本、门禁 owner 不符、任务两行 owner 同步变化及桥期间变化均拒绝，桥前零调用、桥后不重发。复用既有 Lease/Owner 与唯一 SqliteStore，不新增状态机。
- E02：profile 模式 `upsert_snapshot` 在写事务前复用现有 ReadResult 校验并核对 `UnreadSnapshot.profile_id`，不匹配固定 `invalid_input` 且所有表/事件不变；普通 M1 无 profile 模式不变。
- E03：新增 `app/adapters/path_state.py` 的 `probe_path`，只有 `FileNotFoundError` 是明确 missing；普通文件是 file；目录/非普通文件是 other；权限/其它 OSError 是 unknown。gate、activity、profile store、facts 共用；权限错误不再被当 missing，实际 CLI restore 不发布，facts 不返回空结果。
- E04：新增 `app/profile_open.py` 的 `open_profile_store`，facts/run/restore 共用同一 `profile/open_profile` started→唯一 ok/failed 边界；失败只带固定 reason_code，不写事实值、路径或异常原文。
- 保留 D01–D03/D06/D08 修复与既有实际 CLI 合成 eval 闭环；新增同会话领取/续租/失效正例及上述 E01/E02/E03/E04 反例。

## 7 第 3 轮集中返修（F01–F03）

- F01：`session_identity` 改为在一次 SQLite 读取中对同一行执行完整取得时 owner/profile/原库/nonce/held 核验，再构造 `DeviceSessionIdentity`；`verify` 复用同一行核验和既有日志归属，不再 verify 后二次裸读。门禁 nonce 仍独立于任务 nonce，由门禁核对自身会话身份。桥前 nonce 变化零桥调用，桥期间变化桥后拒绝不重发。
- F03：`current_lease_expiry` 复用既有 `validate_lease`，并在同一次任务匹配中加入 `Lease.app`/`Lease.key`；合法同 profile 另一任务 key 与不支持 app 均不能借原 nonce/owner 取得截止，真实续租后的当前截止仍可读。
- F02：补齐 `test_m4c_closed_loop.py` 两个 lstat 注入函数和 `test_profile_facts.py` 一个 permission 注入函数的 docstring，测试语义不变。
- 保留 E02/E03/E04、D01–D03/D06/D08、原 24 判据、唯一 snapshot/事实选择规则和实际 CLI 合成 eval 闭环。

## 8 第 4 轮集成返修（G01–G04）

- G01：与固定 M5 候选正常 merge 后，`device_gate.py` 无文本冲突但 `recover` 仍调用已被维护主线改名的 `self._read_row`。统一改为模块级 `_read_gate_row`，并用真实 `recover` 正反例覆盖原 PID 已停止接管、同 host、未确认、原 PID 运行、无占用与错 profile；不改写原坏占用。
- G02：确认事实写由原先“只读 inspect 后再写”的 TOCTOU 改为固定门禁库 `BEGIN IMMEDIATE` 写事务：同一事务内完成最终占用校验，并持续覆盖目标 profile 打开/迁移与 `set/revoke/forget` 事实提交，结束后回滚/关闭。统一 gate→profile 锁序；异常与进程死亡由 SQLite 释放事务锁；不插入或改写占用行，不改 owner/nonce/state。CLI 用 `ExitStack` 注册 profile close 与守卫退出，profile close 抛错时仍先释放守卫事务并把真实异常传给守卫终态，body 失败不记成完整成功。首次 Windows 确认写可初始化严格验证的空固定门禁库并记录 `facts_guard` started/终态；非 Windows 仅保留结构性事实豁免。
- G03：不同 profile 仍按逻辑放行，但整个写区间保持原子；门禁行状态先于 profile 比较验证，任何不可识别状态、坏 schema、目录/权限不可判定都失败关闭且零目标 profile 创建/迁移/写入。普通锁竞争映射为 `device_busy`，不伪装成动作 unknown/quarantine。
- G04：acquire 改用显式零等待连接，`SQLITE_BUSY` 在 connect/初始化/BEGIN 各层立即映射 `device_busy`，既有 IO 重试不吞 busy；verify/release/recover 保留有界等待与完整身份复核，正常释放可短暂等待事实写事务。确定性跨进程 barrier/event 测试覆盖 set/revoke/forget、事实先持锁时 acquire 立即拒绝、门禁先占用时零 profile 写入、不同 profile 切换、body 异常与进程死亡释放、正常 release 与未知/坏 schema。
- G05：复核所有公共门禁路径后，内部 `_GateBusy` 只在适配器内部分类，不越过端口：真实 SQLite 排他竞争下 verify/release/recover/session_identity 返回既有 `device_busy`，只读 inspect/inspect_gate_occupancy 返回保守 `device_gate_io_error`，activity 由 DeviceGateError 收敛 unknown；acquire 仍零等待 `device_busy`。busy 时原占用、owner/nonce 不变、日志 started 对应 failed 终态，不靠 CLI 通用 except 掩盖；锁解除后同一持有者正常 verify/session_identity 并明确 release。新增真实 `BEGIN EXCLUSIVE` 公共 API/CLI 正反对照。

## 9 验收与未测

已运行：完整 Python 测试（含新事实/门禁/恢复/预检/闭环模块）、Node 断言测试与参考 smoke 回放。测试只用临时项目根、临时 OS 根、合成事实、合成 profile 库、跨进程竞争与合成本机桥桩。

未测：真实 Windows 应用数据目录下的门禁并发/崩溃恢复（仅临时 OS 根模拟）、真实 ADB、真机、真实 provider、私有留出、M5 动作对账、真实额度/冷却扣减、A 档独立前置判据与自动发送。`run check` 通过、`acceptance check` 通过、公开 eval 通过或固定 C 都不构成发送授权或完整 MVP 验收。
