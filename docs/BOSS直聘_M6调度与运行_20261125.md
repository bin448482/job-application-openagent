# BOSS直聘 M6 调度与运行（B1–B8 返修记录）

本文件记录 M6「任务调度、安全点抢占、有界运行闭环」在当前仓库的实现边界、最小持久化契约、生产组合根与未测项。它不构成真实设备、模型、发送或完整 MVP 验收。

## 〇、B1–B8 集中返修结论

- B1/B3：`run execute` 生产组合改为 M3 `load_and_read_fixture`/`is_actionable` → 唯一 `build_envelope`/`render_request`/`decide`；`SceneStep` 只携带 M3 manifest 引用、原始现场（输入/确认框/在途命令）和合成 bridge 响应字段，不把 `task_outcome/read_result/decision` 当权威。非法 intent 被唯一 Decision 契约拒绝，`needs_human/uncertain` 保存待审草稿但任务保持 blocked。
- B2：缓存必须同时命中 `runtime_decisions` 摘要与 `drafts.pending_review` 关联；重核当前 facts、base/pack/model、回复披露/禁谈/事实、任务/共享租约；摘要与草稿不一致时受控拒绝，不静默复用。
- B4：`resume_batch` 在 run 起始原子 paused→active，保留游标/预算/访问历史；只在实际 `start` 后计 `processed`；无 queued 职位是良性跳过，不隔离门禁。restore 活动检查同时把 M6 `jobs` leased/running/blocked 视为 active、active/paused `job_batches` 视为 unknown，避免在运行批次上恢复新包。
- B5：安全点七条件由实际 M3 读取类型、真实 `pending_actions`、`checkpoint_status` 与原始现场派生；批次首任务前先提交初始 checkpoint。
- B6：`prepare`/`execute` 加入过程日志操作白名单，成功路径 stderr 为空并断言 run started/终态。
- B7：预算保留负数在途超支并单列；生产循环以真实单调时钟计耗时、按步骤实际设备调用数扣减；任务/决策前复核共享门禁，TTL60/renew20 路径被调用。
- B8：`apply_job` 不再是纯拒绝；`perform_action` 在显式独立 `ApplyQuotaContract` 下走 pending/授权/真实 `CommandIdentityStore`/执行器/三态/unknown 不重放；生产缺合同仍 fail closed。
- 追加：`FilePolicyRepository.promote` 仅对 Windows `PermissionError`（winerror 5/32）做最多 3 次、50/100ms 的有界同卷 rename 重试，每次重核暂存/目标/链接；其它错误与耗尽仍 `policy_io_error`。

## 二、任务粒度与调度

- 单条发现（`unread`/`new_message`）、单条职位、单条清理候选是任务；职位批次只是身份游标与预算。
- 每次取任务前重算固定优先级：可定位未读 → 新消息候选 → 职位 → 可用清理。当前 M6 不创建 M7 清理表；`SceneCandidates.cleanup` 只有显式候选才可被选中。
- `app/domain/runtime.py` 是唯一纯规则实现：
  - `SafePoint` 七个独立布尔：回列表、输入空、无确认框、无在途命令、无 pending/unknown 动作、动作状态已提交、checkpoint 已提交；任一为假即不是安全点。
  - `select_task`：可定位未读优先；未知未读或无定位正信号只允许一次定向核对，仍未知暂停 `unread_unverified`；职位进行中切换未读先检查抢占上限，达到上限暂停 `preemption_limit`。
  - `BudgetState`：900 秒 / 200 设备调用 / 20 候选 / 30 秒职位 / 5 次抢占；等号停止发起新工作；在途核实可留下负数并单列超支。设备调用与模型调用分开计数。
  - `BatchCursor`：`batch_id`、`last_job_dedupe_key`、`visited_keys`、剩余预算、抢占次数、首次观察墙钟。恢复按当前职位身份顺序，消失跳过、插入/重排不重复；新 round/进程不补预算。
  - `observe_unread`/`build_stage_preempted`：首次观察保留，`waited_ms` 只由单调时钟计算；只有实际切换并开始处理才写 `stage_preempted`；检测间隔单独记。
  - `clock_drift_exceeded`：墙钟与单调时钟增量差超过 1 秒即停止。
- 读取/任务结果未知时不把缺失当零；不存在目标时暂停并保存游标，不伪造消息或职位。

## 三、最小持久化（profile v3）

profile 库由固定路径 `data/runtime/profiles/<profile_id>/runtime.sqlite3` 承载；普通 M1 v1 五表合同不变。v3 迁移先备份，再单事务追加/重建：

- `jobs`：每条职位任务一行；只存 `job_key`/`dedupe_key`/`batch_id` 与规范状态/租约列，不存职位正文。
- `job_batches`：批次游标 + 状态 + `last_checkpoint_id`；`cursor_json` 严格解析，新进程不重置预算。
- `drafts`：本机可重审草稿；绑定 profile/task/subject/input/base/pack/model/model_config/facts 摘要与档位/意图/回复；不携带授权、nonce 或租约。
- `runtime_decisions`：最小运行时决策记忆；键含 profile、subject、task kind、input、base、pack、model、model_config、facts 摘要；只存决策枚举/摘要，不存 HR 正文或回复正文。检索只在全部当前身份一致时命中；命中后仍重读事实、验收与运行租约，且不把命中当本轮模型成功或授权。
- `scheduler_events`：调度白名单事件（`run_started/run_finished/checkpoint_committed/stage_preempted/round_paused/unread_verified/draft_saved/decision_reused/job_* /batch_resumed`）；不写正文、坐标、身份原值。
- `action_records` 因加入第六动作与职位任务而重建：新增 `task_kind`、`discovery_task_key`、`job_task_key`。数据库层保留类型化外键到 `hr_discoveries` 或 `jobs`，并有 CHECK 保证恰好一个非空且等于 `task_key`；迁移前校验完整身份/DDL，备份后单事务重建并保留旧 discovery 动作、索引、IME 与审计行。

事务边界：

- `save_checkpoint` 在同一 `BEGIN IMMEDIATE` 更新游标并写 `checkpoint_committed`；事件写失败整体回滚。
- `pause_batch` 原子保存游标与暂停原因。
- `claim_job/start_job/renew_job/finish_job` 复用唯一 `device_lease`、TTL 60 秒、renew 20 秒与双时钟检查；`finish_job` 进入 blocked 时保留隔离设备行，其余删除。
- `begin_action/complete_action` 对 `apply_job` 复用同一 pending/授权/命令账本/三态/人工对账路径；`Evidence.effect=applied`。

## 四、实际 run 生命周期

CLI：

- `python -m app run prepare --pack <pack>`：显式准备/升级 profile v3；先取得固定 OS 共享门禁排他，再打开/迁移 profile，失败保留隔离。
- `python -m app run execute --pack <pack> --mode read_only|draft_only --fixture <场景> [--confirm-device ...]`：实际有界运行。
- `python -m app run check ...` 保持 M4c 预检语义，不冒充 run。

`app/usecases/runtime.py`：

- 先校验 mode/本轮确认/当前验收；`auto_send_tier_a` 仍固定拒绝。
- `execute_run` 先 `gate.acquire`，再 `gate.verify`、打开 profile、检查未决活动，之后才打开唯一 `SqliteStore`（`require_runtime=True`）。整轮持有共享门禁。
- `read_only` 只读当前可见观察与过程审计：不导航、不消费未读、不调用模型、不写任务/草稿/决策业务行、不隐式迁移；`run prepare` 是显式 schema 准备入口。
- `draft_only` 走同一调度/存储/读取/决策流程；决策前重算允许事实摘要、重读当前验收与运行租约；保存草稿但不自动 apply/send。单职位达到 30 秒时完成在途结果、单列超时并暂停，不发起后续工作。
- 批次预算/安全点/双时钟/抢占在每次新工作前检查；暂停保存游标。正常安全退出才 `release(converged=True)`；前置/时钟/设备不确定保留隔离。
- 合成场景由 `app/adapters/simulated/runtime.py` 的 `FixtureM3Read` 调用真实 M3 解析/门禁，`SyntheticDecisionBridge` 只提供原始 bridge 响应；`SceneStep` 只含 manifest 引用、原始现场与响应字段，不含 `expected/oracle/verdict/answer`。生产组合根经 `RepositorySnapshot`、`ProfileSessionLease`、唯一 `decide`、同一调度/存储/读取/动作链运行；真实 M3 标定/设备/模型入口保持未测，未调用 provider。

本节记录活动分支在固定 c4 上补的三处真实生产接线；仍为离线合成与临时 profile/OS 根证据，不构成真机、真实 provider 或完整 MVP 验收。

- G1：`app.usecases.runtime.derive_safe_point(*, store, batch_id, task_key, read_results, raw) -> SafePoint` 是 `execute_run` 与独立模块探针共用的唯一七条件派生入口，已替换私有 `_safe_scene`。`list_returned` 只认严格有效的 `JobList`、`UnreadRead` 或 `page=chat_list` 页面，完整职位详情/会话/unknown/失败读取都不算；`input_empty/confirmation_closed/no_inflight_command` 取 `RawScene`；`no_pending_action` 取真实 `pending_actions`；`action_state_committed` 使用本轮最近一次真实 `claim/start` 成功的任务身份查询 `last_action_state`（会话键经 `hr_discoveries.conversation_key` 关联真实发现键，职位键直接匹配），`None` 仅表示本轮尚未成功 start（历史已收敛动作不阻断，真正未决动作由第五条件拦截），非法身份保守为假；不回退全局最近动作，也不要求任务仍在当前读取现场；`checkpoint_committed` 要求 `last_checkpoint_id` 非空且真实 `checkpoint_committed` 事件计数 >0。已收敛历史动作不会永久阻断新一轮；同一一致真实仓储下，第六项为假时其非提交状态必被第五项命中，这一真实不变量保留，不用无关历史或非法行凑“七种单假”。`execute_run` 仍保留启动检查点初始化与每个 started 任务后的真实提交。
- G2：`SceneStep.targeted_read_fixture` 是可选原始输入引用（旧场景 JSON 不变）；`selection.verify_unread` 分支在普通读取完成后先按可信单调钟结算普通采集耗时并复核预算/双钟/门禁，再经唯一 `RuntimeReadPort.read` 实际执行一次定向 M3 解析，不重试。设备调用按 `read.take_device_calls()` 真实扣减，普通读取、边界回调、定向采集、安全点后到实际 start 的区间都按累计毫秒折算整秒并保留亚秒余量；缺能力、读取失败、类型不符、过期/未来、重放、错 app/profile 或无明确目标都暂停 `unread_unverified`，不从旧 `unread_verification` 提示清除，并先保存已用预算/游标。命中后候选只从真实新采集的 present 行派生并替换被替换前的旧读取，安全点/处理消费当前采集；合法全覆盖 absent 视为已核实无未读、不生成会话候选，viewport 角标消失与“有计数无定位”仍未知。统一 `usecases.read.targeted_verification_outcome` 对 M2 保持原 `stop_reason_for`，对 M3 增加同新鲜度/身份约束的类型分派，不复制第二套业务权威。过程日志只用 `stage=run/operation=unread` 的 started→单一 ok/undetermined/failed、固定原因/耗时/设备计数，不写 XML、正文或会话身份。
- G3：`execute_run(..., on_boundary=None)` 的观察者只在 `after_checkpoint`/`after_refresh`/`before_safe_point`/`before_claim` 四个真实边界被调用，返回值忽略，只能改变原始外界刺激、推进注入可信时钟或记录轨迹；到达本身不是生产信号。首次观察在本次原始采集/解析完成的真实边界取样，`after_refresh` 注入不得倒灌已结束读取；`after_checkpoint` 后的新到达只能由下一次真实读取观察。`_handle_job/_handle_discovery` 在真实 `claim/start` 成功后立即回调取样器，`build_stage_preempted` 的 `handling_started_at/waited_ms` 只用该新墙钟/单调读数，不使用安全点旧 tick 或处理完成时间；claim 失败/未 start 零 `stage_preempted`、零抢占扣减。`before_claim` 后重新复核门禁、双钟漂移与预算，并把区间耗时计入同轮预算；新增读取/边界/开始区间均按累计毫秒保留亚秒余量，不因多次 floor 永久漏计。六条件预算、五次抢占、第六次暂停、身份游标、双时钟、续租与每命令 nonce 复核保持。
